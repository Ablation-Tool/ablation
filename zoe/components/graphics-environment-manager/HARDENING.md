# GEM hardening record

> Canonical master validation record copied from Ablation. It documents the upstream workbench's test history; standalone verification is reported separately during release checks.

This document records the stress-testing scope, defects found and fixed, verification evidence, and remaining limits of the GEM workbench. It is not an enterprise certification, formal qualification, or claim that every possible failure has been exhausted.

## Defects found and fixed

| Area | Defect | Hardening change |
|---|---|---|
| Concurrent initialization | Multiple processes could append the artifact root more than once. | Added a separate initialization lock and revalidation under lock. |
| Event readers | Reads could observe an in-progress append and malformed records could reach the UI. | Added shared read locks, exclusive write locks, and per-record schema validation. |
| Event graph | Self-parenting and longer cycles were accepted, making nodes unreachable. | Rejects cycles during emission and when loading the event graph. |
| Repeated events | Identical upserts and repeated needs-work notes grew the log unnecessarily. | Suppresses identical events and makes the human needs-work annotation idempotent. |
| Identifiers | The initial ASCII-only identifier rule rejected legitimate Unicode nodes. | Bounded Unicode identifiers with whitespace/control-character rejection. |
| Selection | A missing selected node or deleted/corrupt state could break actions. | Falls back to the artifact root, reports corruption, and handles vanished selections without a Tk exception. |
| Deep trees | CLI and native recursive rendering failed around one thousand levels. | Iterative CLI and native rendering; tested at 1,500 levels. |
| Empty filters | A valid filter with no matches looked like a crashed/blank application. | Added explicit no-match guidance and a working Reset filters action. |
| Expansion state | Refresh discarded expansion below the artifact root. | Preserves expansion at every depth when the node still exists. |
| Corruption | Malformed JSON, missing fields, or bad state raised repeated Tk callback errors. | Reports a visible session error without repeated callback failure; Reset remains usable. |
| Large discovery sets | One lock and `fsync` per event made thousands of discoveries take minutes. | Added `emit_many` with the same validation and one lock/sync per batch; replay remains idempotent. |
| Batch atomicity | A later invalid event could leave a partial batch behind. | Validates and cycle-checks the whole batch before appending any event. |
| Process shutdown | An embedded CLI ignoring SIGHUP blocked window close indefinitely. | Bounded wait, SIGKILL escalation, and final process reaping. |
| GTK multi-terminal shutdown | `Application.run()` could return before VTE delivered child-exit events or completed OS-level reaping, leaving terminal processes or zombies behind. | Stops all workspaces first, preserves SIGKILL escalation for live children, and gives VTE the normal reaping window. If VTE has reported exit but a zombie remains after that bounded wait, a nonblocking `waitpid` fallback reaps only that exited child and handles ownership races explicitly. Repeated tab-close, final-shutdown, and real-zombie fallback tests verify process IDs are gone. |
| Tk teardown | Scheduled callbacks fired after their window was destroyed. | Cancels refresh, poll, and render callbacks during close. |
| Directory targets | The launcher rejected material directories. | Supports real top-level directory inventory, idempotent rescans, directory selection, and file/directory session isolation without a fake content hash. |
| Session placement | A session could be created inside the directory being inventoried. | Rejects target-contained sessions before creating files. |
| Agent command representation | `GEM_CLI` contained a multiword Python command but the agent guide quoted it as one executable name. | Uses an executable session-local wrapper that preserves arguments and works with paths containing spaces; tested through the exact shell command given to the agent. |
| Terminal input validation | Direct handler tests did not cover desktop focus, shifted keys, clipboard operations, or Unicode-to-PTY delivery. Focus CLI and terminal clicks could also target a text widget without activating its window. | Focus CLI and terminal clicks now deiconify, raise, and activate the workbench before focusing the terminal. Targeted Tk events and a real interactive fixture verify focus restoration, keyboard input, clipboard operations, and Unicode handler-to-PTY delivery. |
| Partial terminal writes | Nonblocking PTY writes could drop data or close the terminal after backpressure. | Queues writes, preserves order, retries after temporary blocking, and rejects pastes larger than 8 MiB. |
| I/O-error shutdown | A terminal marked exited after an I/O error could leave a live child and wait indefinitely during close. | Tracks reaping separately, always bounds close, escalates from SIGHUP to SIGKILL, and tests a live stubborn child after an injected I/O failure. |
| Timer lifecycle | Forced renders, resize, refresh, and write flushes could create duplicate callbacks after teardown. | Makes each scheduler single-instance and cancellation-safe; close is idempotent. |
| Metadata and event corruption | Invalid metadata, event versions, timestamps, and incomplete batch records were not consistently rejected. | Validates metadata and record schemas explicitly and tests atomic failure handling. |
| Workspace density and details scrolling | Permanent details crowded the tree, the disabled text view had misleading scrolling, and expanded GTK metadata could push actions off-screen. | Keeps details collapsed by default. GTK uses a height-bounded native disclosure with wrapped labels so actions and status remain visible; the Tk fallback retains full-height wrapped details. |
| GTK details visibility | The details container toggled, but `no_show_all` left its labels invisible; disclosure also rebuilt both charts unnecessarily. | Shows labels once at construction and toggles only their parent. Tests activate the real button, require mapped labels with nonzero allocation, and verify no chart rebuild. |
| Tree/chart layout | Replacing the tree with a chart forced users to switch contexts instead of navigating both together. | A nested native `Gtk.Paned` keeps the tree beside either chart while the outer divider retains the CLI. Initially hidden pages are explicitly shown at construction, and chart selection continues to reroot the shared model. This is the only workspace arrangement. |
| Native desktop integration | Opening untrusted artifacts through a generic handler could execute them, and the native interface needs real Ubuntu behavior rather than a theme imitation. | Uses installed GTK/VTE with a native `Gtk.Application`, `Gtk.TreeStore`, `Gtk.ToggleButton`, `Gio.SimpleActionGroup`, `Vte.Terminal`, and Vanilla icons with attribution. Tk remains a fallback. **Show in Files** invokes Nautilus with `--select` only after an explicit action, with argument-based process launching and no shell or artifact execution. |
| Column sizing | Independently draggable GTK columns could retain excessive width and prevent the investigation pane shrinking. | Removed per-column drag targets. Lab flexes and ellipsizes long labels, Type and Status have bounded fixed widths, and outer/nested dividers control the split. Columns become compact only for a docked chart and restore otherwise. Tests check long labels and narrow/wide pane positions. |
| Idle rescan controls | GTK `show_all()`, including a parent notebook's full-window show, revealed the progress bar and Cancel button when no rescan was active. | Marks both `no_show_all` so only an explicit rescan can reveal them, while retaining hidden-state restoration. Production startup and active-rescan tests verify both idle and active visibility. |
| Font and text contrast | Hard-coded gray and status colors had poor contrast against Ubuntu's dark theme, and the terminal overrode the configured font. | Uses the configured Ubuntu interface and system monospace fonts and lets GTK select theme text colors; explicit user font choices remain respected. Tests cover system-font defaults, saved font preferences, and the absence of custom tree foreground colors. |
| GTK test lifecycle | Directly constructed test windows could survive cleanup and interfere with desktop focus; manually registered applications shared lifecycle state across tests and earlier invalid setup crashed in GTK/GIO. | `AblationWindow` is a plain `Gtk.Window` attached through `add_window()` during normal startup, so direct widget tests no longer violate application startup. Widget tests destroy windows and pump events; normal `Application.run()` behavior is tested in a fresh process. Repeated GUI validation can run in an isolated Xephyr display with software rendering. |
| Investigation isolation | Multiple terminals could otherwise overwrite one selection and mix discoveries into one history. | Each notebook tab has its own numbered session, event log, selection, wrapper, and VTE child. Tests exercise the actual `+` button with two live CLIs, independent discoveries, tab close, and restart restoration without deleting history. |
| Per-tab terminal directories | New terminals inherited one workspace, forcing multi-target users to keep all command-line work in the session tree. | A native folder chooser runs before session creation. Each Lab validates and atomically persists its own terminal directory without changing the RE target or event history. Cancellation and invalid paths create no tab or session; restoration reuses valid directories, warns and falls back for deleted ones, and honors `--workspace`. Tests verify the real child cwd through `/proc`, environment agreement, persistence, override behavior, fallback, and 40 creation/teardown cycles without modal dialogs. |
| Workspace and terminal retention | A tree filter strongly owned `visible_row`, and child exit left the delayed `kill_agent` callback active. Every closed workspace and VTE object remained retained despite process cleanup. | Cancels the kill timeout on child exit and uses a weak workspace reference for filtering. A 100-cycle single-process test verifies all child PIDs are reaped, closed objects are released, tracked object counts stay flat, and memory stabilizes at 81 MiB from a 79 MiB baseline. |
| Agent startup and tab teardown | Async startup experiments were unreliable in nested VTE testing; deferred callbacks and notebook tab labels could retain closed workspaces; failed spawns could leave invalid PIDs. | Uses the proven synchronous VTE spawn path with duplicate prevention and explicit failure state. Deferred starts are tracked and cancelled on close, tab labels are destroyed and cleared, and failed spawns clear the PID. Tests cover real two-tab lifecycle, duplicate starts, failure handling, and 40-cycle object retention. |
| Navigation and presentation | Raw target/session text and a permanent CLI label crowded the header; hiding status and node actions in a disclosure made routine investigation state and controls hard to reach. | Uses visible Lab/Type/Status columns and breadcrumbs, natural-width node actions that compact to icons without wrapping, and an independent eye-icon details disclosure. The centered window title is replaced by the far-left supplied PNG branding icon without losing the window-manager title. Target/session paths remain in Preferences, and the canonical divider position is retained through reloads. |
| Preferences and layout | Users need readable terminal palettes without unsafe process handling or unnecessary workspace variants. | Uses one canonical Lab/tree + optional chart + CLI arrangement. Preferences contains only collapsed Lab, Terminal, and ANSI palette sections, with Apply and errors visible. Legacy layout fields are ignored on load and dropped on save. Tests verify collapsed visibility, custom palettes, preference persistence, canonical pane parents, and both live process IDs after applying settings. |
| Investigation map | Large hierarchies need visual navigation without implying that area equals analysis coverage or that palette color equals status. Rebuilding buttons during resize left invalid allocations, and fixed size requests could prevent shrinking. | Optional treemap built from native GTK buttons with Baobab's position/depth palette and explicit text status. Reuses buttons by identity, updates their CSS providers in place, and assigns exact rectangles during the container's allocation pass without a resize callback. Tests cover shrinking, expansion, hidden-to-visible geometry, button identity, palette independence from status, pagination, selection, and deep trees. |
| Investigation rings | Thin/deep branches can become invisible, and an attractive disk-usage-style chart could misleadingly imply byte or completion measurements. | Adapts Baobab 49.1's annular geometry, palette, minimum angle, five visible descendant levels, and continuation markers using subtree-node units. Explicit captions, tooltips, omitted-node counts, selected outlines, keyboard navigation, and shared selection preserve meaning. Tests cover real Cairo rendering, hit-testing, resizing, depth changes, 250 thin siblings, and a 1,500-node chain. |
| Native tab and row behavior | GTK notebook action widgets can remain hidden, and Yaru does not expose the attempted odd-row CSS selector. | Explicitly shows native `+`/menu controls and tests their signals. Alternating cell backgrounds are derived from theme base/text colors, with native selection colors preserved. |
| Review presentation and undo | Raw enum labels, repeated type text, long names, and a crowded action row increased navigation effort; generic artifact-review advice could also erase meaningful status distinctions. | Uses display-only human labels for all eight statuses and seven node types, hides Type only when matching rows share one type, middle-ellipsizes Lab names with full tooltips, and moves secondary actions into an overflow menu. Footer counts are real filters. Undo appends the complete prior event instead of rewriting history; parent statuses, bookmarks, and the Lab/CLI layout remain independent. Tests verify filtering, accessible action names, exact status/source/note restoration, and unchanged history prefixes. |

## Repeatable validation

Run from the `gem-lab` directory in the Ablation checkout with the desktop dependencies installed:

```bash
python3 stress/run_stress.py
python3 stress/native_stress.py
python3 stress/desktop_input_stress.py
python3 stress/gtk_stress.py
```

The desktop-input and GTK suites require a real X11 display. On a Wayland session with Xwayland, set `DISPLAY` to the Xwayland socket if it is not already exported (commonly `:0`). The desktop-input suite uses targeted Tk events for focus, keyboard, and clipboard checks, and tests Unicode at the terminal handler boundary. It preserves the prior clipboard where possible and restores focus defensively. The GTK suite checks normal application startup in a fresh process; direct widget tests destroy their windows to prevent focus leakage into later tests.

Scale can be adjusted without editing the harness:

```bash
GEM_STRESS_DEEP=1500 GEM_STRESS_LARGE=5000 GEM_STRESS_DIRECTORY=1000 \
  python3 stress/run_stress.py
GEM_STRESS_DEEP=1500 GEM_STRESS_LARGE=5000 \
  python3 stress/native_stress.py
```

## Full-system freeze investigation

- The previous boot ended after a VTE test spawn at 16:22:57, with the next boot about six minutes later. This is a correlation with live GUI/VTE testing, not proof of a VTE defect.
- Historical accounting immediately before the freeze showed **27,679,756 kB available memory**, **96.84% idle CPU**, **0.11 one-minute load**, no swapping, and no material disk queue. This rules out ordinary RAM, CPU, swap, and disk exhaustion at that interval.
- Kernel logs contained no matching OOM kill, GPU hang, kernel panic, or thermal emergency. The host uses Intel Iris Xe graphics through `i915`; a compositor, graphics-driver, kernel, firmware, or hardware cause remains possible but unconfirmed. Earlier GTK/GIO test-process crashes were addressed by correcting the window lifecycle, and do not by themselves explain a full-machine freeze.
- No embedded GEM agents or test terminals remained after shutdown. The user's primary CLI was left running.
- Ten nested X11/software-rendering iterations passed **100 GTK integration tests and 10 desktop workflows** without lifecycle warnings or leftover test processes. The reusable launcher independently passed all 11 GUI checks and cleaned up its Xephyr server. Final memory availability was about 27.9 GB with no swap use.
- A subsequent single-process churn test found that the filter and kill-timeout callbacks retained every closed workspace and terminal. Those lifecycle leaks are fixed. After 100 cycles, tracked object counts stayed flat, all child processes were reaped, and memory stabilized at 81 MiB from 79 MiB. This confirms a real GEM defect and its correction, but does not establish that it caused the earlier hard stop; the historical system had ample resources.
- These results establish stability of the tested application workflows in the isolated environment. The final normal-desktop validation also passed all 63 core/native/GTK/desktop checks, including the real two-tab lifecycle. A window-manager-free Xephyr display can produce misleading multi-tab VTE failures, so that lifecycle is validated on the normal desktop. None of this proves that the host Wayland/graphics-stack freeze is fixed.

## GEM and Lab adversarial hardening

| Area | Defect or risk | Correction and proof |
|---|---|---|
| Concurrent exports | Two writers could select and populate the same run directory. | Exclusive writer locks allow one winner; the competing writer is rejected and the surviving run replays successfully. |
| Artifact writes and failures | Partial writes and injected disk failures could leave ambiguous run state. | Artifacts use temporary files, `fsync`, and atomic replacement. Injected failures release the writer lock. |
| Stale visual evidence | An agent could export after the human changed selection. | Export accepts an expected revision and rejects stale selections before creating a run directory. |
| Snapshot coherence | Lab state and event data could be read from different moments. | A locked investigation snapshot uses one event map and refreshes the selected event from that map. |
| Agent process lifecycle | A timeout could leave descendants running after the parent stopped. | Timeout tests verify termination of the complete process group, including a child process. |
| Unbounded agent output | A noisy or malicious agent could exhaust memory or terminal consumers. | Output is read into bounded temporary files and rejected beyond the declared limit. |
| Small-device geometry | Valid half-pixel rounding at CGA/VGA sizes exceeded smaller tolerances and broke connector invariants. | Default tolerance includes half-pixel quantization; the exact three-node CGA/VGA regression and real investigation export pass. |
| Entropy analysis | `ablation analyze --entropy` called a nonexistent `EntropyMapper.scan`. | The caller consumes `EntropyMapper.run()` and formats its regions. The real system-binary command and Lab evidence/replay workflow pass. |
| Filesystem and parser safety | Resolved run symlinks could bypass validation; oversized metafiles were not bounded. | Run paths are checked before resolution, artifact symlinks are rejected, and metafiles have a 64 MiB limit. Stale locks fail explicitly without deleting evidence. |
| Windows agent cleanup | POSIX-only process-group termination could raise on Windows and leave an agent and its descendants running after timeout. | Shared platform process handling uses bounded `taskkill /T /F` followed by parent termination on Windows and process-group termination on POSIX. Local tests cover both branches; the native Windows suite includes real descendant termination. |
| Windows Unicode input | Treating ConPTY's byte-count result as a character count rejected valid multibyte writes and could split queued UTF-8. Console encoding also needed an explicit contract for Python children. | Uses byte counts consistently, retains incomplete UTF-8, checks invalid counts, and defaults Python children to UTF-8 without overriding explicit user settings. Tests cover blocked, partial, multibyte, and split input; native ConPTY checks use a real interactive fixture. |
| Rendering and replay resources | Extreme scene proportions could request enormous Cairo surfaces, replay inputs were read before total-size validation, and the METRIX bridge buffered unbounded pipes. | PNG dimensions are limited to 16,384 per side and 16,777,216 pixels, replay input is capped at 256 MiB with a 1 MiB manifest, and both agent bridges use the same bounded-output runner. |

The current GEM-focused suite contains 160 checks: 55 core, 26 native, 34 GTK/map/rings/GEM, 32 GEM environment/engine/native, one complete desktop workflow, and 12 universal-installer checks. The real integration test performs `ablation analyze` on a safe system binary, records scoped evidence, and replays the exported run. These tests demonstrate specific behavior, not every possible failure or an enterprise certification.

## Remaining limits and residual risk

- **Platform coverage:** local validation uses Linux with GTK3/VTE, Tkinter, POSIX PTYs, `fcntl`, and an X11 display, including Xwayland on Ubuntu. Native Windows uses Tk with ConPTY; native macOS uses Tk with a POSIX PTY. The current release candidate must pass the real Windows and macOS workflows before `main` is updated; local Linux and mocked platform checks are not substitutes for those runs or formal enterprise certification.
- **Agent compatibility:** Kimi and local interactive fixtures were exercised. Claude Code, Codex, and other terminal agents need their own escape-sequence and interaction validation.
- **Workspace scale and preferences:** two simultaneous real VTE CLIs were tested, not an unbounded number of agents. One root preference set applies to every tab; there are no per-tab profiles or named custom scheme collections. The Tk fallback remains single-investigation and does not provide the GTK notebook/preferences interface.
- **Input coverage:** targeted Tk events tested real Tk focus and keyboard bindings, while Unicode was tested at the handler-to-PTY boundary. This is not a physical-keyboard, input-method, screen-reader, or every-window-manager certification.
- **VTE API:** startup intentionally retains the proven synchronous `spawn_sync` path. Although VTE 0.84 marks it deprecated, the asynchronous migration was not reliable enough to ship. Startup, failure, duplicate-start, two-tab, shutdown, and retention behavior are validated on the normal desktop; any future async migration must pass those same tests rather than rely on an assumed binding or callback contract.
- **Agent execution environment:** the interpreter and packages must remain accessible to the agent's command runner. Sandbox or filesystem restrictions must be handled by choosing an accessible installation, not bypassed.
- **Scale:** tested depth is 1,500, visible siblings are 5,000, and real top-level directory inventory is 1,000 additional entries. There is no multi-gigabyte log test or long-duration soak test. Large logs are read fully into memory and there is no event rotation; rendering scale beyond the native GTK/Tk tests is not guaranteed.
- **Directory coverage:** initialization and rescanning are intentionally top-level only. Directory identity is path-based, not a content digest. No recursive filesystem watcher or automatic recursive inventory is provided.
- **Single-event writes:** `emit` rereads and validates the current graph. High-volume producers should use `emit_many`; no throughput guarantee is made for long sequences of individual events.
- **Durability:** batch writes use a file lock and `fsync`, but this is not a transactional database. Directory-level crash persistence, power-loss recovery, and automatic log repair are not implemented or certified. Corrupt files are rejected and shown, not silently repaired.
- **Integrity and trust:** the log is not signed or encrypted. Validation detects malformed data, not a malicious actor writing plausible but false evidence. The external agent inherits the user's permissions and can modify session files and artifacts.
- **Conflict semantics:** the latest event for an ID wins. There is no collaborative merge protocol beyond the append-only history.
- **AI correctness:** tests cover interaction and evidence propagation, not an agent's analytical accuracy, vulnerability verdicts, or security of a target binary.
- **Accessibility:** automated tests cover keyboard flows, descriptive labels, status roles, text alternatives, persistent palettes, and WCAG normal-text contrast ratios. Manual validation with NVDA, Narrator, VoiceOver, braille displays, and users' individual assistive configurations remains required; no complete accessibility certification is claimed.
- **Dependencies:** no dependency vulnerability scan, SBOM review, formal threat-model sign-off, or enterprise qualification was performed.
- **Teardown coverage:** stubborn SIGHUP-resistant children were tested, not every possible process-tree, daemonization, or terminal-driver behavior.

These limits should guide the next hardening stage rather than being hidden behind a general "enterprise-ready" claim.
