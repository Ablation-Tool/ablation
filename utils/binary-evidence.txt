RFC COMPLIANCE:
  RFC 5080 §2.2 requires: if Access-Request includes Message-Authenticator,
  the Access-Accept MUST include Message-Authenticator.
  RFC 2865 does not mandate Message-Authenticator on Access-Accept.
  Cisco ASA does not require or validate Message-Authenticator on
  Access-Accept in any known version. The attack exploits this gap.

RELATED CVE:

  a different attack vector. F1/F2 exploit the Access-Accept response path
  using only the known RADIUS shared secret.

FINDING F2: RADIUS Class Attribute Buffer Overflow (LINA)
=============================================================

ROOT CAUSE:
  Extraction loop at 0x03a4bfa4 allows OU= values up to 256 bytes.
  Cisco ASA CLI enforces a 64-character maximum for group-policy names.
  The strncpy at 0x01a30894 uses a runtime-sourced length bound ([r15+0x08]).
  If that runtime bound exceeds the actual array size at session+0x0c,
  a 65-256 byte OU= value overwrites adjacent session struct fields.

EVIDENCE:
  Extraction cap:  0x100 = 256 bytes  (CMP rax,0x100 at 0x03a4bfa4)
  CLI-enforced max: 64 chars           (ASA group-policy name limit)
  strncpy bound:   runtime [r15+0x08] from attr_def table 0x76f20a0
  Array type:      inlined char[] at session+0x0c
                   (estimated 32-256 bytes; exact size requires runtime)

EXPLOITATION PATH (if max_length > array size):
  1. Inject OU= value of 65-256 bytes (poc_radius_ou_inject.py --f2)
  2. strncpy copies beyond end of group_policy_name array
  3. Adjacent session struct fields overwritten
  4. Fields between session+0x0c+array_end and session+0x1a78 are unknown;
     corruption of function pointers or callbacks may enable code execution
