  Summary of previous vendor communications:
  Initial disclosure submitted to Cisco PSIRT (psirt@cisco.com) on 2026-08-13
  via Cisco's PSIRT online submission portal. No acknowledgment or response

  Multiple vendors affected: No

  Product: Cisco Adaptive Security Appliance (ASA) — LINA process

  Version:
  All versions. Binary analysis confirmed in 9.14.2.14 (BuildID 65cd0306...)
  and 9.22.2.32 (BuildID 88929a4c...). Systemic across all ASA releases.
  Partial opt-in mitigation exists only in 9.22.x train.

  Significant ICS/OT impact? YES (Cisco ASAs are perimeter devices widely
  deployed in critical infrastructure and ICS/OT environments)

  Related to AI/ML systems? No

  ---
  What is the vulnerability?
  Two related vulnerabilities in Cisco ASA LINA (the monolithic firewall
  process, x86-64 stripped PIE ELF) affecting RADIUS-based VPN authentication:

  == F1: RADIUS Class Attribute Group Policy Substitution ==

  Cisco ASA does not validate the Message-Authenticator attribute (RFC 2865
  attr 80; RFC 5080 §2.2) on incoming RADIUS Access-Accept packets before
  processing the Class attribute (attr 25) for VPN group policy assignment.
  Function 0x03a4bda0 in the LINA binary parses the Class attribute for an
  "OU=<value>" pattern and uses the extracted value as the VPN group policy
  name for the authenticated session. No Message-Authenticator validation
  exists anywhere in the call chain.

  Binary analysis (9.22.2.32):
  - strstr("OU=") at 0x03a4bee6
  - Three callers (0x3a4c365, 0x3a4c3fe, 0x3a4c5b9) — none validate attr 80
  - Group policy name written to session struct offset 0x0c via:
    0x3a4bda0 -> 0x3a4a250 -> 0x1a330a0 -> 0x1a30710 -> strncpy@0x1a30894
  - Confirmed in 9.14.2.14, 9.16.x binaries

  Cisco silently added a `message-authenticator-required` sub-command in the
  9.22.x train (string at 0x4a6ef70) without issuing a CVE or advisory. The
  command is disabled by default. All versions prior to 9.22.x have no
  mitigation path.

  == F2: RADIUS Class Attribute Buffer Overflow ==

  The OU= extraction loop in 0x03a4bda0 reads up to 256 bytes (loop bound at
  0x3a4bfa4: cmp rax, 0x100). The ASA CLI enforces a 64-character maximum for
  group-policy names. The extracted string is written to session+0x0c via
  strncpy, with the copy length sourced from a runtime-populated attribute
  definition table at 0x76f20a0. If the runtime max_length exceeds the actual
  inlined array size at session+0x0c, a OU= value of 65-256 bytes overwrites
  adjacent session struct fields.

  Known adjacent fields:
  - session+0x0c:   group_policy_name (inlined char array, ~32-256 bytes)
  - session+0x1a78: session_type (DWORD)
  - session+0x31a8: vpn_state_machine (DWORD)

  Runtime verification in progress on authorized test environment.

  BuildIDs: 9.22.2.32=88929a4c3f35a2c0786e01e63c2e64626666ef23,
            9.14.2.14=65cd0306770da18bb71c057dc0dd1472391a1569
  No existing CVE covers these findings. CVE-2024-3596 (BlastRADIUS) targets
  Access-Request MD5 collision injection — a different attack vector.

  ---
  How does an attacker exploit this vulnerability?
  Prerequisites:
  1. RADIUS shared secret for the ASA's aaa-server group
  2. Network position to inject/intercept RADIUS Access-Accept traffic
     (MitM between ASA and RADIUS server, or compromised RADIUS server)
  3. A legitimate user actively authenticating to the targeted ASA

  F1 Attack Steps:
  1. Intercept RADIUS Access-Accept response for an active authentication
  2. Replace or insert a Class attribute (type 25) containing:
     "OU=<target_group_policy_name>;"
  3. Recompute the Response-Authenticator using the known shared secret:
     MD5(Code || ID || Length || Request-Auth || Attrs || Secret)
  4. Deliver the modified Access-Accept to the ASA
     -- No Message-Authenticator (attr 80) is required; ASA accepts without it
  5. ASA assigns the attacker-specified group policy to the user's VPN session

  F2 Extension (if runtime-confirmed exploitable):
  Same setup; pad OU= value to 65-256 bytes to trigger overwrite of session
  struct fields adjacent to group_policy_name at session+0x0c.

  ---
  What does an attacker gain?
  F1: VPN group policy escalation. Attacker assigns any named group policy on
  the ASA to the victim session, potentially granting:
  - Access to network segments restricted by the legitimate policy
  - Bypass of ACL enforcement tied to the correct group policy
  - Full-tunnel routing where split-tunnel was intended
  - Elevated session parameters (time limits, simultaneous logins, etc.)

  The victim user's credentials are not exposed. Exploitation requires only
  the shared secret and network position — not any user password.

  F2 (pending runtime verification): Session struct corruption in the LINA
  process (runs as root on ASA). If corruption reaches function pointers or
  callback tables in the session struct, the primitive may extend to code
  execution. Minimum impact without code execution: session state corruption,
  unexpected VPN behavior, or targeted session termination.

  Systemic exposure: Every ASA configured for RADIUS-based VPN authentication
  is affected by F1 by default. No mitigation exists before 9.22.x. In 9.22.x,
  the mitigation is present but disabled by default.

  ---
  How was the vulnerability discovered?
  Static binary reverse engineering of official Cisco ASA firmware images
  downloaded directly from Cisco's software portal.

  Method:
  1. Extracted LINA ELF from firmware: asa9-22-2-32-smp-k8.bin -> CPIO
     rootfs -> asa/bin/lina (105MB x86-64 stripped PIE ELF)
  2. Located RADIUS Class attribute parsing via string anchors ("OU=" at
     vaddr 0x43b7581, log format "OU=%s (tunnelgroup %s)\n" at 0x497c510)
  3. Traced function 0x03a4bda0 through all callers confirming no attr-80
     validation in any path
  4. Traced group policy name assignment through six function layers to
     confirm session struct destination (session+0x0c)
  5. Cross-validated in 9.14.2.14 and 9.16.x firmware images
  6. Verified against CVE databases: not covered by any existing CVE
