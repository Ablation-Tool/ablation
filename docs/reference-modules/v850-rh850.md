# Renesas V850 / RH850 Lifting & Taint Analysis

Decode V850/RH850 instructions, produce structural pseudo-C through `BinaryLifter`, and trace taint using the V850 EABI. The implementation supports common V850 and RH850 instruction families rather than claiming complete coverage of every core extension.

## Structural lifting

```python
from ablation.analyzers.binary_lifter import BinaryLifter

lifter = BinaryLifter.from_path('/path/to/rh850.elf', arch='rh850')
print(lifter.lift_function(0x10000))
```

`v850` and `v850e2` select the same backend. It invokes `v850-elf-objdump`, which must be installed and available on `PATH`. Calls, branches, and returns are emitted structurally; unmodeled instructions remain comments. This is not full C recovery.

## ELF taint analysis

```python
from ablation.analyzers.taint_tracker_v850 import V850TaintTracker

tracker = V850TaintTracker.from_path('/path/to/rh850.elf')
findings = tracker.run()
paths = tracker.run_interprocedural(depth=4)
print(tracker.report(findings))
```

`from_path()` accepts an optional ISA `variant`, defaulting to `Variant.RH850`. The binary-oriented API returns `TaintFindingV850` objects and models `r6`–`r9` arguments plus `r10`/`r11` returns.

## Analyze an existing objdump listing

```python
from ablation.analyzers.taint_tracker_v850 import V850TaintTracker

tracker = V850TaintTracker.from_path('/path/to/rh850.elf')
findings = tracker.run_from_listing(objdump_text, label='candidate')
```

`run_from_listing()` and `run_from_objdump()` use the lower-level labeled `Finding` API. Their results differ from `run()`; do not mix field expectations between the two. The lower-level `TaintEngine` can also consume `ablation.analyzers.insn_v850` instruction iterables directly.

## Architecture details

The V850 EABI uses `r6`–`r9` for the first four integer arguments and `r10` for the primary return value. `r31` (`lp`) holds the link/return address. `prepare` and `dispose` instructions affect stack and saved-register analysis. RH850 atomic and extended encodings require explicit decoder support; they are not interchangeable with ARM or MIPS instructions.

## Limitations

- Structural lifting requires the external V850 objdump toolchain. Native taint decoding and listing-based analysis are separate paths.
- Function boundaries, ROM load addresses, and direct-call resolution determine coverage. Raw ROM users must supply correct address mappings.
- Saved-link-register warnings and taint paths are candidates, not proof of an overwrite or attacker reachability.
- Memory aliases, indirect calls, loops, and depth limits can create false positives or missed flows.
- Check any security-relevant pseudo-C or finding against the original V850/RH850 instructions.
