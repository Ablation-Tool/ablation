### CAP-A10-01: EcuArchDetector — flat ECU ROM ISA identification

- **name:** EcuArchDetector
- **category:** ISA Detection / ECU
- **paths:** `ablation/analyzers/ecu_arch_detector.py`
- **entry point:** `EcuArchDetector(data)` | `EcuArchDetector.from_path(path)` | `.from_bytes(data)` → `.detect()` → `ArchDetectResult`
- **what it does:** Fingerprints the ISA of a raw flat ECU ROM image (no ELF/IHEX/SREC
  header) by running 8 discriminator functions. Returns best-match architecture with
  confidence (HIGH≥0.75, MEDIUM≥0.40, LOW<0.40) and a human-readable reason string.
- **inputs:** raw bytes (file path or buffer). Optional `sample_size` (default 4096 bytes).
- **outputs:** `ArchDetectResult(arch, score, confidence, reason)`. `candidates()` returns
  all scored results.
- **scope — 8 discriminators:**
  1. `arm_cm` — Cortex-M: LE MSP in SRAM range + Thumb-mode reset vector
  2. `tricore` — AURIX: PFLASH pointer density (full image scan); BMHD gate + SH-2 vector
     gate + BE artifact guard prevent false positives from M68K/SH-2A ROMs
  3. `m68k` — M68K/CPU32: BE reset vector + LINK.W A6 density
  4. `ppc32` — PPC32 Book E: primary opcode density in PPC ranges
  5. `ppc_vle` — VLE: (byte0 & 0x90)==0x10 halfword density
  6. `sh2a` — SH-2A: BE reset VA + RTS/STS.L PR density
  7. `m32r` — Renesas M32R: IVT16 + dense4 slot pattern at 16-byte / 4-byte strides
  8. `c166` — C166/C167: 64 consecutive 4-byte IVT entries starting with opcode 0xFA (JMPS)
- **status:** implemented; M32R discriminator added 2026-10-10 (gap-17); C166 added for BMW MS43
- **evidence:** tests/test_ecu_arch_detector.py (BMHD gate, SH-2 vector gate, M32R vs PPC false-positive)
- **docs:** ecu-arch-detector.md AND ecu-architecture-detector.md — BOTH exist for the same file.
  ecu-architecture-detector.md is a newer, more detailed doc with mermaid flowchart.
  Both are accurate to the code. Duplicate docs are a RAG hazard (retrieval may return
  either; neither is wrong, but having two creates noise).
- **DISCREPANCY:** README ISA list does NOT include M32R (Hitachi 5EAT TCU) or C166/C167
  (BMW MS43/Bosch KW1) — these two ISAs are implemented and confirmed but undocumented in
  the README. docs/architecture.md ISA tier table similarly omits them.

### CAP-A10-02: EcuRomLayoutAnalyzer — ROM region classification

- **name:** EcuRomLayoutAnalyzer
- **category:** ISA Detection / ECU
- **paths:** `ablation/analyzers/ecu_rom_layout_analyzer.py`
- **entry point:** `EcuRomLayoutAnalyzer(data, arch_hint=None)` | `from_path()` | `from_bytes()` → `.analyze()` → `list[RomRegion]`
- **what it does:** Segments a flat ECU ROM into labeled regions: ERASED, CODE, CALIBRATION,
  MIXED, PADDING, IVT. Uses Shannon entropy + fill-byte ratio + PPC opcode density (default)
  or Capstone TriCore decode density (when `arch_hint="tricore"`).
- **inputs:** raw bytes + optional arch_hint string. Default 4-variable decision
  (entropy + fill ratio + PPC opcode density).
- **outputs:** `list[RomRegion(offset, size, region_type, arch_hint)]`. Also:
  `is_calibration_only() → bool` (detects OBD cal-only dumps with no CODE regions).
- **scope:** All 8 ECU ISAs for region classification. TriCore gets Capstone decode density
  for CODE/CALIBRATION discrimination. PPC32/VLE use opcode density.
- **confirmed targets:** GM E38 PCM (PPC32), Bosch EDC16C34 (TriCore)
- **status:** implemented
- **docs:** ecu-rom-layout-analyzer.md — matches code accurately.

### CAP-A10-03: EcuC166Decoder — C166/C167 pure-Python decoder

- **name:** EcuC166Decoder
- **category:** ISA Decoder / ECU (pure-Python)
- **paths:** `ablation/analyzers/ecu_c166_decoder.py`
- **entry point:** `EcuC166Decoder(data, base_pa=0)` | `from_path()` | `from_bytes()` → `.disassemble()` | `.function_starts()` | `.scan_xram_loads()` | `.scan_xram_stores()` | `.parse_ivt()`
- **what it does:** Decodes Infineon C166/C167 instructions from a raw ROM buffer.
  Pure-Python (Capstone has no C166 support). Handles 2-byte and 4-byte opcodes.
  `function_starts()` scans for CALLS (0xDA) instructions and returns all call targets.
  `parse_ivt()` extracts the 64-entry Interrupt Vector Table starting at ROM base.
  `scan_xram_loads/stores()` finds all instructions referencing a specific XRAM address
  (useful for locating seed buffer initialization in SecurityAccess handlers).
- **inputs:** raw bytes + optional base_pa physical address.
- **outputs:** `list[C166Insn]` from disassemble(). `list[int]` from function_starts().
  `list[IVTEntry]` from parse_ivt(). `list[C166Insn]` from scan_xram_loads/stores().
- **scope — 14 instruction types:** MOV_IMM, CMP_IMM, ADD_IMM, JMPS, CALLS, MOV_LD,
  MOV_ST, MOV_REG, ADD_REG, XOR_REG, MOVBZ, MOVBS, MUL_REG, MULU_REG
- **4-byte ops (0xDA=CALLS is function_starts trigger):** 0xE6, 0x66, 0x46, 0x06, 0xFA,
  0xDA, 0xF2, 0xF6, 0xC2, 0xA2, 0xB2
- **confirmed targets:** BMW MS43 WBABW510X0PK46741 512KB ROM (byte-verified)
- **status:** implemented
- **docs:** c166-c167-decoding.md — matches code.

  inverter control units and motor-drive ECUs compiled with cl2000 or c29clang.
- **status:** implemented

  ti-c28x-decoding.md is more detailed (SPRU430F sourcing). Duplicate RAG risk.

### CAP-A10-05: EcuM68kDecoder — M68K/CPU32 Capstone decoder

- **name:** EcuM68kDecoder
- **category:** ISA Decoder / ECU (Capstone-backed)
- **paths:** `ablation/analyzers/ecu_m68k_decoder.py`
- **entry point:** `EcuM68kDecoder(data, base_va=0)` | `from_path()` | `from_bytes()` → `.disassemble()` | `.function_starts()`
- **what it does:** Decodes M68K/CPU32 instructions using Capstone CS_ARCH_M68K/CS_MODE_M68K_020.
  `function_starts()` is pure-Python (no Capstone round-trip): scans for LINK.W A6 (#-N)
  (frame-allocating functions, opcode 0x4E56) and MOVEM.L regs,-(SP) (0x48E7) for
  callee-save-only leaf functions. Guards against counting MOVEM that immediately follows
  a LINK (which would be the 2nd instruction, not a new function start).
- **inputs:** raw bytes + optional base_va.
- **outputs:** `list[M68kInsn]` with same field conventions as VLEInsn (pipeline-compatible).
- **scope:** GM P-series PCMs: P01, P04, P05, P08, P10, P11, P59 (CPU32 derivative of 68020)
- **dependencies:** capstone (CS_ARCH_M68K). `disassemble()` requires it; `function_starts()`
  and `insn_length()` are pure-Python and work without it.
- **status:** implemented
- **docs:** ecu-m68k-decoder.md — accurate.

### CAP-A10-06: EcuSH2aDecoder — SH-2A pure-Python decoder

- **name:** EcuSH2aDecoder
- **category:** ISA Decoder / ECU (pure-Python)
- **paths:** `ablation/analyzers/ecu_sh2a_decoder.py`
- **entry point:** `EcuSH2aDecoder(data, base_va=0)` | `from_path()` | `from_bytes()` → `.disassemble()` | `.function_starts()`
- **what it does:** Decodes Renesas SH-2A (SH7058/SH7059) instructions. Pure-Python

- **inputs:** raw bytes + optional base_va.
- **outputs:** `list[SH2aInsn]`; sorted VAs from function_starts().
- **scope:** Renesas SH7058/SH7059 MCUs found in Honda (CBR250RR, ECU 38770-K87-J01),
  Subaru (SH7058S, EcuFlash corpus), and other Japanese OEM ECUs.
- **status:** implemented
- **docs:** ecu-sh2a-decoder.md — accurate.

### CAP-A10-07: EcuVLEDecoder — PowerPC VLE pure-Python decoder

- **name:** EcuVLEDecoder
- **category:** ISA Decoder / ECU (pure-Python)
- **paths:** `ablation/analyzers/ecu_vle_decoder.py`
- **entry point:** `EcuVLEDecoder(data, base_va=0)` | `from_path()` | `from_bytes()` → `.decode_one()` | `.disassemble()` | `.function_starts()`
- **what it does:** Decodes PowerPC VLE (Variable Length Encoding) instructions from a raw
  ROM buffer. Mixed 16-bit (SE16) and 32-bit VLE/Book E instructions; width determined by
  (byte0 & 0x90)==0x10 for 32-bit, otherwise 16-bit.
  `function_starts()` scans for `e_stwu r1, -N(r1)` (frame-allocating, unique in ECU code)

  that is the 2nd instruction in an e_stwu prologue.
- **inputs:** raw bytes + optional base_va.
- **outputs:** `list[VLEInsn]`; sorted deduplicated VAs from function_starts().
- **scope:** NXP e200z4/z6/z7 cores on GM E39, E39a, E54, E92 ECUs.
- **status:** implemented
- **docs:** ecu-vle-decoder.md — accurate.

### CAP-A10-08: EcuSecurityAccessScanner — static-seed SecurityAccess fingerprinter

- **name:** EcuSecurityAccessScanner
- **category:** Vulnerability Scanner / ECU
- **paths:** `ablation/analyzers/ecu_security_access_scanner.py`
- **entry point:** `EcuSecurityAccessScanner(data)` | `from_path()` | `from_bytes()` → `.scan()` → `list[SecurityAccessFinding]`
- **what it does:** Detects UDS/KWP2000 SecurityAccess handlers that always return a static
  (non-random) seed. Scans raw ROM bytes for the instruction pattern where the
  requestSeed handler stores 0x67 (subfunction code) as the first seed byte then zeros the
  rest — any key derived from this seed is predictable, allowing unauthenticated access to
  protected diagnostic services.
- **inputs:** raw bytes + optional `window` (default 256 bytes for disassembly context).
- **outputs:** `list[SecurityAccessFinding(arch, offset, pattern_desc, window_bytes)]`
- **scope — 3 architectures:**
  1. **M68K/CPU32** (GM P-series P01/P04/P05/P08/P10/P11/P59): `move.b #$67, <mem>` +
     `clr.b <mem+1>` + `clr.b <mem+2>` pattern
  2. **PPC32** (GM E38): `li rX, 0x67` + `stb rX, N(rA)` + `li rY, 0` + `stb rY, N+1(rA)`
  3. **PPC VLE** (GM E92 NXP e200z): `se_li rX, 0x67` + `se_stb rX, N(rA)` (SE16)
     or `se_li rX, 0x67` + `e_stb rX, N(rA)` (VLE32, for regs outside r0-r7)
- **confirmed targets:** Full GM ECU corpus (patterns confirmed in
  `targets/automotive/auto_ecu_corpus_re.py`, gitignored)
- **status:** implemented
- **docs:** ecu-security-access-scanner.md — accurate.

### CAP-A10-09: Calibration parsers — ECU label maps and calibration tables

Five parsers produce `CalibrationTable` / `CalibrationAxis` objects (shared types in
`ecu_cal_def.py`) and `label_map()` dicts for injection into `BinaryContext`.

#### CAP-A10-09a: EcuXDFParser (TunerPro XDF)

- **paths:** `ablation/analyzers/ecu_xdf_parser.py`, `ecu_cal_def.py`
- **entry point:** `EcuXDFParser.from_file(path, base_address=0)` → `.label_map()` | `.calibration_tables()`
- **what it does:** Parses TunerPro XDF files (XML). Handles shared axes (DALINK), per-table
  endianness overrides, linear MATH equations, address-relative and absolute file offsets.
  `label_map()` → `{file_offset: name}` for BinaryContext injection.
- **scope:** XDF format; used for GM (most models), Ford, misc OEM platforms.
- **docs:** no dedicated xdf doc found in reference-modules/ — MISSING reference doc.

#### CAP-A10-09b: EcuA2LParser (ASAM A2L / ASAP2)

- **paths:** `ablation/analyzers/ecu_a2l_parser.py`, `ecu_cal_def.py`
- **entry point:** `EcuA2LParser.from_file(path)` → `.label_map()` | `.calibration_tables()`
- **what it does:** Parses ASAM MCD-2 MC (ASAP2 v1.3x/v1.61) A2L files. Supports
  RAT_FUNC COMPU_METHOD (rational polynomial scaling), RECORD_LAYOUT, CHARACTERISTIC,
  and AXIS_PTS blocks.
- **scope:** Bosch EDC16/EDC17/MED17, Continental, Delphi, Siemens, most OEMs.
  A single EDC16 A2L covers 3,999 CHARACTERISTICs; large EDC17 covers 25,000+.
- **docs:** ecu-a2l-parser.md — accurate.

#### CAP-A10-09c: EcuConecanParser (conescan XML)

- **paths:** `ablation/analyzers/ecu_conescan_parser.py`, `ecu_cal_def.py`
- **entry point:** `EcuConecanParser.from_file(path)` → `.identify_rom(rom)` | `.label_map()` | `.calibration_tables()`
- **what it does:** Parses ConnorRigby conescan ECU definition XML format used for Mazda
  SH705x and SH7055 ECUs (MX5, RX8). `identify_rom()` checks for xmlid string match at
  internalidaddress (±search_window).
- **scope:** Mazda MX5, RX8 (SH7058 / SH7055 cores). Single-ROM XML format (no base/variant split).
- **docs:** ecu-conescan-parser.md — accurate.

#### CAP-A10-09d: EcuOpenDamosParser (open_damos.json)

- **paths:** `ablation/analyzers/ecu_open_damos_parser.py`, `ecu_cal_def.py`
- **entry point:** `EcuOpenDamosParser.from_file(path)` → `.calibration_tables()` | `.locate_in_rom(rom)` | `.label_map(rom=None)`
- **what it does:** Parses the open_damos.json format (open-car-reprog / Poisson48). Key
  feature: **fingerprint relocation** — each axis carries numeric fingerprint (expected
  physical breakpoint values), so `locate_in_rom()` can find tables in any ROM variant of
  the ECU family without knowing addresses a priori.
- **scope:** PSA/Bosch EDC16C34 firmware variants (confirmed). Same JSON works across
  software generations regardless of address differences.
- **docs:** no dedicated open-damos doc found — MISSING reference doc.

#### CAP-A10-09e: EcuRomRaiderParser (RomRaider XML)

- **paths:** `ablation/analyzers/ecu_romraider_parser.py`, `ecu_cal_def.py`
- **entry point:** `EcuRomRaiderParser.from_file(path)` → `.identify_rom(rom)` | `.calibration_tables(variant_id)` | `.label_map(variant_id)`

### CAP-A10-10: V850Decoder — Renesas V850 pure-Python decoder

### CAP-A10-11: ARCDecoder — Synopsys ARC decoder (Capstone-optional)

- **name:** ARCDecoder / ARCDisasm
- **category:** ISA Decoder (tool-dependent tier)
- **paths:** `ablation/analyzers/arc_decoder.py`

- **inputs:** raw bytes + base_addr. Optional endian.
- **outputs:** `ARCFrame` records with is_call, is_branch, is_ret, target.
- **scope:** Synopsys DesignWare ARC EM/HS (IoT MCUs, smart TVs, storage controllers,
  automotive SoCs), ARC 770D (Linux-capable), ARC HS38/HS48 (SMP Linux).
- **status:** partial (full decode only with capstone next; otherwise frame-walking only)

### CAP-A10-14: HiSiRV32Ext — HiSilicon RISC-V custom extension correct-size decoder

- **name:** HiSiRV32Ext (hisi_rv32_ext.py)
- **category:** ISA Decoder / Platform Extension
- **paths:** `ablation/analyzers/hisi_rv32_ext.py`
- **entry point:** Module-level decode functions; used by the RISC-V taint tracker to
  correct Capstone misalignment on custom opcodes.
- **what it does:** Fixes Capstone 5.x mishandling of HiSilicon WS63 / Hi3863 / BS21
  (Hi2821) NearLink SoC "riscv31" ISA extensions. Six custom opcode spaces:
  - `0x0b` custom-0: ldmia/stmia (multi-register load/store)
  - `0x7b` custom-3: R-type dispatch/context (~9000 hits in WS63-liteos-app)
  - `0x5b` custom-2: muliadd (`rd = rs1 + (rs2 * zero_ext(uimm))`)
  - `0x3b` OP-32: beqi/bnei/bgei/blti/bgeui/bltui (branch-immediate)
  - `0x1b` OP-IMM-32: addshf/orshf/andshf/xorshf/subshf (shift-fused ALU)
  - `0x1f` reserved: **l.li** (6-byte variable-length long load-immediate — CRITICAL for
    alignment correctness; Capstone treats as 4-byte, causing 2-byte cascade misalignment)
  Also handles 16-bit RVC reuse slots: uxtb/uxth (zero-extend byte/half).
- **scope:** HiSilicon WS63 / Hi3863 / BS21 (NearLink protocol SoCs). Source: fbb_ws63 SDK +
  HiSilicon-patched GCC 7.3.0 / binutils 2.38.
- **status:** implemented
- **docs:** hisi-rv32-ext.md AND hisilicon-risc-v-extensions.md — **two separate docs** for
  the same file. RAG duplication risk.

### CAP-A10-15: EpilogueShareScanner — shared epilogue block detector

- **name:** EpilogueShareScanner
- **category:** CFG / Function Boundary Analysis
- **paths:** `ablation/analyzers/epilogue_share_scanner.py`
- **entry point:** `EpilogueShareScanner(ctx)` → `.scan()` → `list[EpilogueShareHit]`
  Results injected into `BinaryContext.shared_epilogues` to let `run_interprocedural()` skip them.
- **what it does:** Finds functions that share an epilogue via unconditional jump. When
  compiler merges tail blocks, `run_interprocedural()` may treat the shared block's address
  as an independent function entry, creating phantom taint paths. The scanner identifies
  those entry-point impersonators by finding unconditional jumps whose targets land
  strictly inside another function's address range (not at its entry point).
- **scope:** TriCore only (currently). Uses Capstone CS_ARCH_TRICORE + tricore_const.
  `_TRICORE_UNCOND_JUMP = {'j', 'ja', 'jl', 'jla'}`.
- **dependencies:** capstone (CS_ARCH_TRICORE + CS_MODE_TRICORE_162), lief (optional).
- **status:** implemented (TriCore only); other ISAs not yet supported.
- **docs:** epilogue-share-scanner.md — accurate.

### CAP-A10-16: FlatBinaryFuncStartScanner — arch-agnostic function-start scanner

- **name:** FlatBinaryFuncStartScanner
- **category:** Function Discovery / ECU
- **paths:** `ablation/analyzers/flat_binary_func_start_scanner.py`
- **entry point:** `FlatBinaryFuncStartScanner(data, base_va=0)` → `.scan()` → `FuncStartResult`
- **what it does:** Finds probable function entry VAs in flat (headerless) ECU ROM images
  using two strategies combined: (1) call-target harvesting — follows reset vector, decodes
  branch/call instructions for detected ISA, recursively collects all reachable call targets;
  (2) prologue pattern scan — byte-scans for ISA-specific prologue sequences.
  Uses `EcuArchDetector` for ISA selection: HIGH/MEDIUM confidence → single-ISA catalog;
  LOW confidence → all 5 catalogs unioned.
- **inputs:** raw bytes + optional base_va.
- **outputs:** `FuncStartResult(arch, confidence, function_starts, call_targets, prologue_hits,
  detect_result)`
- **scope:** All ECU ISAs supported by EcuArchDetector (arm_cm, tricore, m68k, ppc32,
  ppc_vle, sh2a, m32r, c166). Catalogs for all 8 — though c166 uses the IVT JMPS pattern
  for additional discovery beyond CALLS scan.
- **status:** implemented
- **docs:** flat-binary-func-start-scanner.md — accurate.

### CAP-A10-17: TiCoffLoader — TI COFF2 / AR archive parser

- **name:** TiCoffLoader
- **category:** Binary Format Parser
- **paths:** `ablation/analyzers/ti_coff_loader.py`
- **entry point:** `TiCoffLoader.from_path(path)` → `.symbols()` → `Iterator[CoffSymbol]`
- **what it does:** Parses Texas Instruments COFF2 object files (.obj) and AR archives (.a)
  produced by TI Code Generation Tools (cl2000, c29clang, tiarmclang). Extracts symbol
  table entries with storage class, value, and section binding. Handles C_UEXT (storage
  class 19) — TI's weak-symbol equivalent for `__attribute__((weak))` mapped by cl2000.
- **inputs:** file path (any TI COFF2 magic 0x00C2 or AR `!<arch>\n` magic).
- **outputs:** `Iterator[CoffSymbol(name, value, storage_class, storage_class_name, section)]`
- **scope — 5 target IDs:** TMS320C2800 (C28x), C6000, C5500, C5500+, MSP430
- **storage classes:** C_EXT (2), C_STAT (3), C_EXTREF (5), C_LABEL (6), C_UEXT (19)
- **status:** implemented
- **docs:** ti-coff-loader.md AND ti-coff-archive-loading.md — two docs. ti-coff-archive-loading.md
  is focused on archive traversal; ti-coff-loader.md is the primary reference. Both accurate.

### CAP-A10-18: TiNNCScanner — TI Neural Network Compiler artifact scanner

- **name:** TiNNCScanner
- **category:** Vulnerability Scanner / AI-MCU
- **paths:** `ablation/analyzers/ti_nnc_scanner.py`
- **entry point:** `TiNNCScanner.from_path(path)` → `.scan()` → result; `.report(result)` → str
- **what it does:** Detects TVM-generated `tvmgen_*` symbols in firmware compiled by TI NNC
  (ti_mcu_nnc v2.x, built on Apache TVM). Identifies security risks from weak/C_UEXT
  normalization symbols that can be silently overridden by a subsequently linked object.
- **inputs:** ELF (ARM Cortex-M33/M4/R5/M0+, C29x) via lief, or TI COFF2/AR (C28x) via
  TiCoffLoader.
- **outputs:** `result` with list of findings. Text report via `.report()`.
- **scope — 4 finding classes:**
  - TINCC-001 HIGH: Weak normalization symbol override risk (`tvmgen_default_bias/scale/shift_data`)
  - TINCC-002 MEDIUM: NPU async completion flag ordering hazard
  - TINCC-003 MEDIUM: Multi-model NPU contention (sequential enforcement required)
  - TINCC-004 INFO: Skip-normalize mode active (manual normalization required)
- **supported TI MCU targets:** F28P55x (C28x), MSPM0 (Cortex-M0+), CC2745/AM13x (Cortex-M33),
  CC1352 (Cortex-M4), AM26x (Cortex-R5), F29H85x (C29x)
- **dependencies:** lief (ELF targets), TiCoffLoader (C28x COFF targets)
- **status:** implemented
- **docs:** ti-nnc-scanner.md AND ti-neural-network-artifacts.md — two docs. Both accurate.
  ti-sdk-package-sweeping.md and ti-sweep.md cover the sweep workflow that uses this scanner.
