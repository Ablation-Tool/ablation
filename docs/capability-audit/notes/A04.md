## Capability Records

### 1. TaintTracker (base x86-64 intraprocedural)

- **name:** `TaintTracker`
- **file:** `ablation/analyzers/taint_tracker.py`
- **category:** Taint Analysis
- **entry point:** `TaintTracker(binary_path: str)`, then `trace_function(func_va, tainted_args, max_insns=800, max_func_size=0x2000)`
- **what it does:** Intraprocedural linear-scan taint tracker for x86-64 stripped ELF binaries. Seeds taint from external `tainted_args` list (no built-in sources). Propagates through register moves and stack slots, detecting five sink categories: alloc_size, copy_len, mem_write, branch_cond, call_arg.
- **inputs:** ELF binary path (str), function VA, list of tainted argument register names
- **outputs:** `List[TaintSink]` — each with VA, sink type, tainted register
- **scope:** x86-64 ELF; intraprocedural only; no PLT source resolution
- **status:** implemented
- **API note:** No `from_path()` or `from_context()` classmethod — direct constructor only. Does not follow the standard Ablation API pattern. This is a deviation from `ablation/core/architecture.md` which states all tools have `from_path()` or `from_context()`.
- **stack model:** rbp-relative and rsp-relative slots; all 16 GP 64-bit registers tracked
- **limitations:** No interprocedural propagation; no built-in taint sources; no CFG (linear scan). Manual seed required.
- **known-anomalies doc:** MISSING (no `reference-anomalies/` entry)
- **reference docs:** `docs/reference-modules/taint-analysis.md` (covers x86 taint broadly)
- **tests:** `tests/test_taint_x86.py` (partially — primarily exercises taint_tracker_x86.py)

### 2. TaintTracker (full interprocedural x86-64)

- **name:** `TaintTracker` (in `taint_tracker_x86.py`)
- **file:** `ablation/analyzers/taint_tracker_x86.py`
- **category:** Taint Analysis
- **entry point:** `TaintTracker(binary_path, xref=None, func_starts=None, custom_sinks=None, custom_sink_vas=None)`
- **what it does:** Full interprocedural x86-64 taint tracker with MFP (monotone framework / fixed-point) worklist over CFG. Tracks data-flow from 17 network/input sources to ~35 dangerous sinks. Supports both linear scan and CFG-based MFP interprocedural analysis. Includes taint forwarding through string/memory copy functions.
- **methods:**
  - `run()` — intraprocedural scan all functions
  - `run_interprocedural(depth=4)` — BFS interprocedural with configurable depth
  - `run_flow_sensitive()` — flow-sensitive CFG-based analysis
  - `run_on_function(func_va, func_end_va)` — single function
  - `run_on_function_seeded(func_va, seed_arg_indices)` — seeded for interprocedural callees
  - Module-level: `analyze_function()`, `analyze_function_seeded()`, `analyze_function_flow_sensitive()`
  - CLI: `_cli()` (argparse-based)
- **inputs:** ELF binary path; optional XRefGraph, func_starts, custom sink dicts
- **outputs:** `List[TaintFinding]`; `List[InterproceduralPath]` for interprocedural mode
- **scope:** x86-64 ELF only
- **sources (17):** recv, recvfrom, recvmsg, read, fread, fgets, gets, getline, getdelim, scanf, fscanf, sscanf, readv, pread, pread64, (and likely SSL_read — visible in x86_32 sources)
- **sinks (~35):** system, popen, execve, execl/execvp/execv/execlp/execle, posix_spawn, _system, printf/fprintf/sprintf/snprintf family, syslog, memcpy/memmove/memset family, strcpy/strcat/strncpy/strncat, malloc/calloc/realloc/alloca, open/fopen/unlink/chmod/chown/rename/remove/dlopen/symlink, Tcl_Eval family, lua_dostring family, PyRun_SimpleString, wordexp
- **taint forwarders:** strdup, strndup, g_strdup, xstrdup
- **stack model:** rbp-relative and rsp-relative with delta tracking; 16 GP regs
- **naming collision:** Both this file and `taint_tracker.py` define a class named `TaintTracker`. The simple tracker in `taint_tracker.py` was the original; this is the production version. Importing both in the same namespace causes a silent override. `__init__.py` exports this one (from `taint_tracker_x86`).
- **status:** implemented
- **known-anomalies doc:** MISSING
- **reference docs:** `docs/reference-modules/taint-analysis.md`, `docs/reference-modules/taint-analysis-2.md`, `docs/reference-modules/named-taint-sources-and-bounds.md`
- **tests:** `tests/test_taint_x86.py`, `tests/test_interprocedural.py`, `tests/test_flow_sensitive.py`

### 4. TaintTracker (x86 labeled — instruction-stream variant)

- **name:** `TaintTracker` (in `taint_tracker_x86_labeled.py`)
- **file:** `ablation/analyzers/taint_tracker_x86_labeled.py`
- **category:** Taint Analysis (labeled/bounded)
- **entry point:** `TaintTracker(Mode.X64)`, seed via `taint_register("rdi", "user")`, run via `run(insns)` → `List[Finding]`
- **what it does:** Labeled-taint tracker for x86/x86-64 instruction streams. Assigns named labels and bounds to taint (not just boolean). Supports both 32-bit and 64-bit mode. Consumes structured instruction streams (not raw binary). Designed for unit-level testing and trace analysis, not direct binary RE.
- **state tracked:** regs (with family aliasing, sub-register merge), mem (symbolic frame slots), ranges (rep movs, syscall input buffers), consts (known immediate values), frame_ptrs (registers derived from sp/bp), mem_ptrs (spilled pointer registers), ra_slots (return address locations), eq (register equality classes)
- **bound semantics:** `bound` on a Taint = max attacker-controlled contribution to the value. `movzx eax, dl` → bound 0xff. `lea rax,[rbx+rax*8]` with clean rbx → 0xff*8. Unknown multiply or unbounded add resets bound to None.
- **input sources:** from_listing, from_objdump, from_capstone; NOT from binary path
- **Policy fields:** taint_through_pointer, calls_propagate_to_return, report_tainted_branch, report_tainted_load_addr, report_tainted_store_addr, report_tainted_store_over_ra, report_syscall_args, report_rep_count, bounded_index_is_safe, report_bounded, entry_is_function_start
- **imports from:** `insn_x86` (Imm, Insn, Mem, Reg, rip_relative_target), `isa_x86` (ABI model, instruction classification)
- **status:** implemented
- **known-anomalies doc:** MISSING
- **reference docs:** `docs/reference-modules/taint-analysis.md`, `docs/reference-modules/named-taint-sources-and-bounds.md`
- **tests:** `tests/test_taint_labeled_coverage.py`

### 5. ARM64TaintTracker

- **name:** `ARM64TaintTracker`
- **file:** `ablation/analyzers/taint_tracker_arm64.py`
- **category:** Taint Analysis
- **entry point:**
  - `ARM64TaintTracker.from_path(path, custom_sinks=None, custom_sources=None)`
  - `ARM64TaintTracker.from_path_full(path, ...)` — augments symbols with CFG/XRef data; preferred for stripped binaries
  - `ARM64TaintTracker.from_path_ko(path, ...)` — for Linux kernel modules (.ko)
  - `ARM64TaintTracker.from_context(ctx)` — from BinaryContext
- **what it does:** AArch64 labeled-taint tracker. Tracks data flow from network/input sources to dangerous sinks. Uses TaintEngine (inner class) for instruction-level execution with labeled bounds. Supports both intraprocedural (`run()`) and interprocedural BFS (`run_interprocedural(depth=4)`). Can also run from disassembly listings/objdump.
- **methods:**
  - `run()` → `List[TaintFindingARM64]`
  - `run_interprocedural(depth=4)` → `List[TaintFindingARM64]`
  - `run_from_listing(text, label)` → `List[Finding]`
  - `run_from_objdump(text, label)` → `List[Finding]`
- **inputs:** AArch64 ELF binary path or BinaryContext; custom sink/source sets
- **outputs:** `List[TaintFindingARM64]` (binary mode) or `List[Finding]` (listing mode)
- **scope:** AArch64 ELF + kernel modules (.ko); AAPCS64 (x0-x7 args, x19-x28 callee-saved, x30=lr, x29=fp)
- **sources:** recv, recvfrom, recvmsg, read, fread, fgets, gets, getchar, fgetc + Linux arm64 svc (read/recvfrom syscalls via x8=nr, x0-x5=args)
- **sinks:** system, execve, execl, execvp, execle, execvpe, popen, strcpy, strcat, sprintf, vsprintf, snprintf, vsnprintf, memcpy, memmove, gets
- **key AArch64 semantics:** W-register write zero-extends (bound=0xFFFFFFFF); `and rd, rn, #imm` with positive mask bounds rd; shift/extend modifiers scale bound; ldp/stp pair instructions; pre/post-index writeback
- **TaintEngine:** inner engine class with ISA-level instruction dispatch; step(), _mov(), _alu(), _load(), _store(), _pair(), _atomic(), _svc(), etc.
- **status:** implemented

- **scope:** x86-64 only (absolute address BSS loads characteristic of x86-64)

### 10. TaintedStringTracker

- **entry point:** `TaintedStringTracker.from_context(ctx)` or `from_path(path)`

- **inputs:** BinaryContext (or path); SinkArgClassifier results
- **outputs:** `List[TaintedFormatResult]` — each with original SAC finding + upgraded verdict
- **TaintedFormatResult.verdict():** TAINTED_FORMAT_ARG | RODATA_CONST
- **scope:** x86-64 only; integrates with SinkArgClassifier workflow
- **status:** implemented

### 11. WindowsPoolTaintTracker

- **file:** `ablation/analyzers/windows_pool_taint_tracker.py`

- **pool sinks:** ExAllocatePool, ExAllocatePoolWithTag, ExAllocatePoolWithQuota, ExAllocatePoolWithQuotaTag, ExAllocatePool2, ExAllocatePool3, ExAllocatePoolPriorityUninitialized, ExAllocatePoolUninitialized
- **scope:** x64 PE only; Windows kernel drivers; IAT-resolved imports only (not inline calls); limited to linear taint within function

## Issues / Discrepancies Found

1. **Naming collision:** Both `taint_tracker.py` and `taint_tracker_x86.py` define a class named `TaintTracker`. The `__init__.py` exports the x86 full version. The base version is shadowed. This could cause confusion for anyone directly importing `from ablation.analyzers.taint_tracker import TaintTracker`.

2. **API deviation:** `taint_tracker.py` (base), `taint_tracker_i386.py`, and `windows_pool_taint_tracker.py` lack `from_context()` classmethod. `taint_tracker.py` and `taint_tracker_i386.py` lack both `from_path()` and `from_context()`. The architecture doc (`docs/architecture.md`) states "Every tool has a `from_path()` or `from_context()` classmethod entry point" — these are exceptions.

3. **Missing known-anomalies docs:** Base x86-64 taint trackers (`taint_tracker.py`, `taint_tracker_x86.py`, `taint_tracker_x86_labeled.py`), ARM32 labeled tracker, i386 tracker, BssTaintTracker, and TaintedStringTracker lack reference-anomalies docs. 4 of 11 in this unit have anomaly docs.

4. **Missing tests:** `taint_tracker_i386.py`, `bss_taint_tracker.py`, `tainted_string_tracker.py`, and `windows_pool_taint_tracker.py` have no identified test files. The 85% coverage gate (mentioned in architecture) applies to taint trackers — these may not meet it.

5. **Two i386 trackers:** Both `taint_tracker_x86_32.py` (X86_32TaintTracker) and `taint_tracker_i386.py` (TaintTrackerI386) target i386. X86_32TaintTracker is the more complete one (has classmethods, PIC support, 17 sources, anomaly doc). TaintTrackerI386 appears to be an earlier/simpler variant.

6. **README source count:** README says 17 sources for x86-64; code in `taint_tracker_x86.py` docstring lists 15 visible in first pass (need full read to verify exact count).
