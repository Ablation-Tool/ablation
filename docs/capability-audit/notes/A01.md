## Capability: BinaryContext — session cache and session anchor
- **name:** BinaryContext
- **category:** Binary Parsing / Session Infrastructure
- **paths:** ablation/analyzers/binary_context.py (lines 163–3475)
- **entry point:** `BinaryContext.load_or_build(path, force_rebuild=False)` → BinaryContext; `BinaryContext.build(path)`; `BinaryContext.load_from_cache_file(cache_file, orig_path="")`; `BinaryContext.from_context(ctx)` (in SAC, not here)
- **what it does:** Parses a binary once and caches all derived structures (PLT/IAT, function starts, call graph, string table, string XRef index) as a SHA-256-keyed JSON blob in `~/.ablation/cache/`. Every downstream tool receives this object instead of a raw path, preventing repeated re-parse. Implements per-architecture call-graph construction, PLT/IAT extraction, and string XRef indexing via vectorized numpy routines.
- **inputs:** ELF, PE (.sys/.dll/.exe), AIX XCOFF, M88K COFF, flat ROM (heuristic)
- **outputs:** BinaryContext object with `.plt`, `.exports`, `.func_starts`, `.call_edges`, `.strings`, `.string_xrefs` populated; JSON cache file
- **scope:**
  - ELF architectures: x86_64, x86_32, ARM64 (aarch64), ARM32 (with Thumb detection), MIPS32 BE/LE, MIPS64, PPC32 BE, PPC64 LE (ELFv2), PPC64 BE (ELFv1), RISC-V 32/64, LoongArch64
  - PE: x86_64, x86_32 (via `_build_pe`)
  - AIX: XCOFF32/XCOFF64 (via `_build_xcoff`)
  - M88K: COFF via `_build_m88k`
- **status:** implemented
- **evidence:** tests/ directory (multiple integration tests reference BinaryContext)
- **docs:** docs/reference-modules/binary-context.md, docs/reference-modules/binary-context-additions.md — match code accurately
- **dependencies:** LIEF (binary parsing), numpy (vectorized scans), capstone (Thumb second pass in ARM32 call graph)

### Key sub-capabilities:
**PLT extraction** (`_extract_plt` + per-arch helpers):
- x86_64: standard GOT+PLT stub patterns
- x86_32: 5-byte `jmp [disp32]` stubs (via `_extract_plt_x86_32`)
- ARM32: PC-relative LDR+BX stubs (via `_extract_plt_arm32`)
- PPC32 BE: standard stub sequences (via `_extract_plt_ppc32be`)
- PPC64 LE (ELFv2): 4-word and 5-word stubs + `.glink` fallback (via `_extract_plt_ppc64le`)
- PPC64 BE (ELFv1): 7-instruction, 6-instruction, 5-instruction stub patterns (via `_extract_plt_ppc64be`)
- PE IAT: imports as PLT equivalents (via `_extract_plt_pe`)

**Far-call stub detection** (PPC64LE XLC-GAP-007):
- Pattern A: `addis r12,r2,HI / ld r12,LO(r12) / mtctr r12 / bctr`
- Pattern B: `addi r2 / addis r2 / ld r12,Y(r2) / addi r3 / mtctr / bctr` (C++ vtable thunks)

**func_starts extraction** (`_extract_func_starts`):
- Sources: eh_frame/DWARF CFI, ELF exports, x86_64/ARM64/ARM32/PPC prologues
- Thumb detection via mapping symbols (`$t`, `$a`)
- PE: `.pdata` exception directory (via `_extract_func_starts_pe`)
- XCOFF: SYMS section

**Call graph construction** (per-arch vectorized BL scans + fallbacks):
- `_build_call_graph_ppc`: BL scan (PPC32/64 words), far-call stub detection
- `_build_call_graph_arm32`: numpy BL (0xEB/0xFA MSB scan) + capstone Thumb pass
- `_build_call_graph_arm64`: vectorized BL (0x94–0x97 MSB)
- `_build_call_graph_mips`: JAL scan + LW $t9/$gp + JALR (O32 ABI PIC via `.reginfo`)
- `_build_call_graph_sequential`: capstone-based fallback for other ISAs
- `_build_call_graph_pe`: PE-specific using capstone

**String XRef index** (per-arch, in `_build_string_xref_index` family):
- x86_64: RIP-relative memory operands (ADRP-equivalent)
- ARM64: ADRP+ADD/LDR pattern (`_build_string_xref_index_arm64`)
- ARM32: LDR PC-relative pattern (`_build_string_xref_index_arm32`)
- x86_32: absolute 32-bit displacement (`_build_string_xref_index_x86_32`)
- PPC64: ADDIS+LD/LWZ patterns + pre-call augmentation + array augmentation + two-hop (`_build_string_xref_index_ppc64`, `_augment_xrefs_ppc64_*`)

**Name overlay system:**
- `set_name(va, name, source)` / `set_names_bulk()` / `delete_name()`
- `name(va)` → overlay > export > PLT > hex
- `names_table(limit)` → formatted table

**Diagnostics:**
- `plt_sparsity_warning(threshold)`: detects sparse PLT (stripped binaries)
- `pushad_at_entry()`: x86 pushad at entry-point (anti-analysis indicator)
- `ads_reference_vas()`: ADS (Windows Alternate Data Streams) references
- `cpuid_locations()`: CPUID instruction locations (VM detection)
- `summary(top_n)`: structured summary of binary metadata

**Rebuild and XRef:**
- `rebuild_call_graph()` → re-runs call graph after set_names_bulk
- `build_xref_index(binary_path)` → populates string XRef index on demand
- `callers_of(symbol_or_va)`, `callees_of(func_va)`, `reachable_from(source_vas, depth)`
- `strings_near(va, radius)`, `string_xrefs(string_va)`, `funcs_referencing_string(string_va)`
- `func_containing(va)`: binary search on func_starts
- `export_va(name)`, `plt_name(va)`

## Capability: BinaryLifter — pseudo-C lifter with ISA state machines
- **name:** BinaryLifter
- **category:** Binary Lifting / Decompilation
- **paths:** ablation/analyzers/binary_lifter.py (3000+ lines)
- **entry point:** `BinaryLifter(ctx)`, then `BinaryLifter.lift(func_va)` or `BinaryLifter.with_taint(taint_result)` for annotated lifting
- **what it does:** Converts machine instructions to pseudo-C using per-ISA `NativeVal` register state machines. Each ISA backend tracks register state (`ctype`, `expr`, `is_ptr`, `tainted`, `uses`) and emits C-like assignment statements. The `with_taint()` call injects taint annotations at the register where user input enters the function.
- **inputs:** BinaryContext + function VA
- **outputs:** List of pseudo-C strings with optional taint markers
- **scope (ISA backends):**
  - Full C expression lifting (NativeVal state machines): ARM64 (`_ARM64State`), x86_64 (`_X86_64State`), x86_32 (`_X86_32State`)
  - Structural lifting (BFS walk + comment fallback): ARM32 (`_ARM32State`), MIPS32/64 (`_MIPSState`), PPC32/64 (`_PPCState`), RISC-V 32/64 (`_RISCVState`), LoongArch64 (`_LA64State`), ARC (`_ARCState`), V850 (`_V850State`), nanoMIPS (`_NanoMIPSState`), SH-2A (`_SH2aState`)
  - Per-arch emit functions: `_make_arm32_emit`, `_make_mips_emit`, `_make_ppc_emit`, `_make_riscv_emit`, `_make_la64_emit`, `_make_nanomips_emit`, `_make_arc_emit`, `_make_v850_emit`
- **status:** implemented (full for ARM64/x86-64/x86-32; structural for others)
- **dependencies:** capstone, BinaryContext
- **limitations:** Structural ISAs emit `// comment` for unrecognized instructions; no taint annotation for structural ISAs

### NativeVal:
- `NativeVal(ctype, expr, is_ptr, tainted, uses)` — register slot
- Propagated through moves; taint bit carried through arithmetic/loads

## Capability: BeamContext — Erlang BEAM bytecode analysis
- **name:** BeamContext
- **category:** Language Runtime Analysis / BEAM
- **paths:** ablation/analyzers/beam_context.py (1180+ lines)
- **entry point:** `BeamContext.from_file(path)` or `BeamContext.from_bytes(data)`; `sweep_beam_dir(directory, dangerous_only, exclude_otp)` → List[BeamContext]; `sweep_beam_diff(old_dir, new_dir)` → List[BeamDiffEntry]
- **what it does:** Parses Erlang BEAM bytecode files (`.beam`). Extracts chunks: atoms (AtOM/AtU8), exports (ExpT), imports (ImpT), string literals (StrT/LitU), abstract code (Abst), debug info (Dbgi). Decodes ETF (External Term Format) for literals and AST. Detects obfuscation patterns (missing Abst, encrypted Dbgi, scrambled atoms, high opcode density). BEAMLifter translates BEAM opcodes to pseudo-C.
- **inputs:** `.beam` file bytes
- **outputs:** BeamContext with `.exports`, `.imports`, `.literals`, `.functions` (BeamAstFunction), `.dangerous_calls`, obfuscation score
- **scope:** Erlang/OTP BEAM format (BEAM4 magic), all standard chunk types
- **status:** implemented
- **evidence:** beam_context.py is self-contained with comprehensive parsing
- **docs:** docs/reference-modules/beam.md
- **dependencies:** zlib (chunk decompression)

### Sub-capabilities:
- `sweep_beam_dir()`: directory scanner, filters dangerous calls, excludes OTP stdlib
- `sweep_beam_diff()`: compares two BEAM versions, reports added/removed exports
- `fmt_sweep()`, `fmt_sweep_diff()`: human-readable output formatters
- `_detect_obfuscation()`: heuristic obfuscation detection (Attacker-controlled bytecode)
- `BEAMLifter`: opcode→pseudo-C translator class

## Capability: CFGBuilder — control flow graph construction + security gap analysis
- **name:** CFGBuilder (in cfg_builder.py)
- **category:** Control Flow Analysis
- **paths:** ablation/analyzers/cfg_builder.py (530 lines)
- **entry point:** `CFGBuilder(binary_path, ctx)`, then `.build(func_va)` → CFG
- **what it does:** Uses capstone to disassemble a function and constructs a `CFG` of `BasicBlock` objects with predecessor/successor edges. Also provides three security-specific gap analysis functions: mediation completeness, error-path security gaps, and auth-bypass via error path.
- **inputs:** binary path, BinaryContext, function VA
- **outputs:** CFG object (BasicBlock list + edges); security gap finding lists
- **scope:** Architecture-agnostic capstone-based (all arches capstone supports); security gap functions assume branch-predicated auth check patterns
- **status:** implemented
- **docs:** doc match uncertain — no dedicated cfg_builder reference doc seen
- **dependencies:** capstone, LIEF (section map), BinaryContext

### Security gap functions:
- `find_complete_mediation_gaps(cfg, auth_block_vas)`: identifies paths that bypass auth blocks
- `find_error_path_security_gaps(cfg)`: error-handling blocks that branch to privileged code
- `find_auth_bypass_via_error_path(cfg)`: auth bypass candidates via error paths
- `_write_dot(cfg, path)`: DOT graph export

## Capability: DataflowEngine — generic monotone dataflow framework + analyses
- **name:** MFPEngine, ConstPropAnalysis, ReachingDefsAnalysis, SCCPAnalysis, DomTree, LoopInfo
- **category:** Program Analysis / Dataflow
- **paths:** ablation/analyzers/dataflow_engine.py (1400+ lines)
- **entry point:** `ConstPropAnalysis(cfg, arch_config)`, `ReachingDefsAnalysis(cfg)`, `SCCPAnalysis(cfg, arch_config)`; `DomTree(cfg)`, `LoopInfo(cfg)`
- **what it does:** Implements a generic monotone fixed-point (MFP) engine over a CFG with per-arch transfer functions. Three concrete analyses: constant propagation, reaching definitions, SCCP (sparse conditional constant propagation). Also builds dominator trees and loop information (natural loops via back-edges).
- **scope:**
  - Arch configs with calling-convention seeds and transfer functions: ARM32 (`ARM32Config`), ARM64 (`ARM64Config`), Thumb2 (`THUMB2Config`)
  - Framework is arch-agnostic (new ArchConfig subclass extends it)
- **status:** implemented
- **dependencies:** capstone (CFGBuilder internally), numpy

- **category:** Decompilation / Control Flow Structuring
- **paths:** ablation/analyzers/structurizer.py (300+ lines)
- **entry point:** `Structurizer(cfg).structure()` → StructuredNode tree

## Capability: EntropyMapper — sliding-window Shannon entropy analysis
- **name:** EntropyMapper
- **category:** Binary Analysis / Entropy
- **paths:** ablation/analyzers/entropy_mapper.py (300+ lines)
- **entry point:** `EntropyMapper(window_size, step).analyze(data)` → EntropyMapResult
- **what it does:** Computes Shannon entropy over sliding windows of binary data. Classifies regions as high-entropy (compressed/encrypted), medium, or low. Detects entropy transitions (code→data, plaintext→encrypted). Fast path via numpy; Python fallback.
- **inputs:** raw bytes
- **outputs:** EntropyMapResult with `.windows` (List[EntropyWindow]), `.regions` (List[EntropyRegion]), `.transitions` (List[EntropyTransition])
- **status:** implemented
- **deps:** numpy

## Capability: WindowAnalyzer — disassembly window with pseudo-C annotation
- **name:** WindowAnalyzer
- **category:** Manual Review / Disassembly
- **paths:** ablation/analyzers/window_analyzer.py (400+ lines)
- **entry point:** `WindowAnalyzer(ctx).dump_text(func_va, n_insns)` → str
- **what it does:** Disassembles a window around a function VA using capstone, annotates with register state (using `_canonical_reg`, `_lift_to_pseudo_c`, `_resolve_val`), and names stack variables (`_stack_name`). Produces human-readable annotated disassembly for manual review. Used when automated taint tools don't have the sink configured.
- **scope:** x86_64 (RIP-relative detection via `_parse_rip_target`); arch detection from ELF header
- **status:** implemented
- **deps:** capstone, BinaryContext
