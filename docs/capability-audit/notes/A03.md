## CAP: isa_arc — ARC ISA/ABI Model

- **name**: `isa_arc` module (no dataclass; raw constants + `Decoded` namedtuple)
- **category**: ISA/ABI model
- **paths**: `ablation/analyzers/isa_arc.py`
- **entry point**: Imported by `insn_arc.py`; `canon_reg(name)`, `normalize_mnemonic(m)`, `ARG_REGS`, `RET_REGS`, `SYSCALL_NR_REG`
- **what it does**: Provides the ARC EM/HS 32-bit ISA model. Encodes register conventions, ABI register roles, Linux syscall model (trap_s 0, nr in r8, args r0–r5), and complete mnemonic classification sets (LOAD, STORE, BRANCH, CALL, ARITH, COPY, etc). `normalize_mnemonic()` returns a `Decoded` namedtuple splitting base mnemonic, condition, flags, delay, addressing mode, and sign-extension bit.
- **inputs/outputs**: `canon_reg(str) -> Optional[str]`; `normalize_mnemonic(str) -> Decoded`; frozensets of classified mnemonics
- **scope**: ARC EM and HS cores (ARCv2); ARC32 ABI
- **status**: implemented
- **evidence**: Used by insn_arc.py and ARC taint tracker
- **docs**: Listed in isa-models.md but that doc only explicitly lists isa_arc, isa_arm32, isa_arm64, isa_ppc — does not enumerate isa_mips, isa_riscv, isa_v850, isa_loongarch64, isa_m88k, isa_x86. **Gap: reference doc is incomplete.**
- **limitations**: No dataclass wrapper; ARC HS 64-bit (ARCv3) not covered
- **dependencies**: None (stdlib only)

## CAP: isa_arm32 — ARM32/Thumb ISA/ABI Model

- **name**: `isa_arm32` module
- **category**: ISA/ABI model
- **paths**: `ablation/analyzers/isa_arm32.py`
- **entry point**: Imported by `insn_arm32.py`; `canon_reg()`, `reg_info()`, `normalize_mnemonic()`, `Mode`, `ARG_REGS`, `RET_REGS`
- **what it does**: Provides ARM32/Thumb ISA model. Encodes AAPCS and AAPCS-VFP ABIs, argument registers r0–r3, return r0–r1, Linux syscall (svc #0, nr in r7). `Mode` enum encodes ARM vs THUMB state with `pc_value()` computing PC-relative addresses per ARM ARM A2.3.1 (+8 ARM, +4 Thumb). `normalize_mnemonic()` returns a decoded struct with condition code, sets-flags bit, and width suffix (.n/.w). Full mnemonic sets include IT blocks, VFP/NEON.
- **inputs/outputs**: `canon_reg(str) -> Optional[str]`; `reg_info(str) -> Optional[RegInfo]`; `normalize_mnemonic(str) -> Decoded`
- **scope**: ARM A32, Thumb-2 (T32), ARMv6/v7-A/R; AAPCS, AAPCS-VFP
- **status**: implemented
- **evidence**: Used by insn_arm32.py (from_listing, from_objdump, from_capstone)
- **docs**: Listed in isa-models.md; `pc_value()` documented there accurately
- **limitations**: No VFP/NEON register ABI specifics beyond mnemonic tagging; ARMv8-A 32-bit not explicitly tested
- **dependencies**: None

## CAP: isa_m88k — Motorola MC88100 ISA/ABI Constants

- **name**: `isa_m88k` module (raw opcode tables, no dataclass)
- **category**: ISA/ABI model
- **paths**: `ablation/analyzers/isa_m88k.py`
- **entry point**: `IMM_OPS`, `LDST_OPS`, `BRANCH_OPS`, `BCND_OPS`, `TRIADIC_OPS`, `CTL_OP`, `CTL_SUB`, `BCND_CONDS`, `reg_name()`; ABI constants `ARG_REGS`, `RET_REGS`, `CALLEE_SAVED`, `LINK_REG`, `SP`
- **what it does**: Empirically validated opcode tables for MC88100 derived from Lotus 1-2-3 `moto_gen` BCS COFF binary (1993). Covers immediate-form ops, load/store ops, branch ops (BSR/BSR.N 26-bit PC-relative), conditional branch ops, and triadic integer ops (partial). BCS ABI register roles documented.
- **inputs/outputs**: Dict/frozenset constants; `reg_name(int) -> str`
- **scope**: Motorola MC88100 only; BCS 88Open ABI

- **docs**: m88k-decoder.md accurately describes this module. Not listed in isa-models.md (expected — it is a different class of target).
- **limitations**: Triadic ops (0x3A–0x3C): function code field not decoded; MC88110 (superscalar follow-on) not supported
- **dependencies**: None

## CAP: isa_riscv — RISC-V ISA/ABI Model

- **name**: `IsaModel` frozen dataclass + `Width` enum + utility functions
- **category**: ISA/ABI model
- **paths**: `ablation/analyzers/isa_riscv.py`
- **entry point**: `Width` enum (RV32, RV64); `canon_reg(name) -> Optional[str]`; `isa_for(width) -> IsaModel`; `norm_imm12()`, `andi_bound()`, `andi_propagates()`; `ARG_REGS`, `RET_REGS`, `FP_ARG_REGS`, `FP_RET_REGS`, `SYSCALL_NR_REG`; `SYSCALLS` dict; `INPUT_SYSCALLS` set
- **what it does**: RV32 and RV64 ISA model sourced from RISC-V Unprivileged ISA spec and psABI. `IsaModel` bundles mnemonic frozensets (copy, narrow_copy, fp_copy, call, ret, uncond_jump, cond_branch, load, store, const, alu_rr, alu_ri, csr, fp_arith) all width-parameterized. `andi_propagates()` implements taint-specific logic: a non-negative 12-bit imm bounds a register, a negative (alignment mask) imm does not. Includes C-extension compressed opcodes.
- **inputs/outputs**: `canon_reg(str) -> Optional[str]`; `isa_for(Width) -> IsaModel`; `norm_imm12(int, int) -> int`; `andi_propagates(str, int) -> bool`
- **scope**: RV32I/RV64I + M/A/F/D/C extensions; Linux lp64/ilp32 psABI
- **status**: implemented
- **evidence**: Used by insn_riscv.py; `andi_propagates` is taint-significant
- **docs**: Not listed in isa-models.md. **Gap.**
- **limitations**: No RV32E (embedded) ABI; no RISC-V Privileged ISA (CSR side effects not modeled)
- **dependencies**: None

## CAP: isa_v850 — V850/RH850 ISA/ABI Model

- **name**: `IsaModel` frozen dataclass + `Variant` enum + immediate normalization
- **category**: ISA/ABI model
- **paths**: `ablation/analyzers/isa_v850.py`
- **entry point**: `Variant` enum (V850, V850E, V850E2, RH850); `isa_for(variant) -> IsaModel`; `canon_reg()`, `reg_num()`, `reg_by_num()`; `norm_imm16_zext()`, `norm_imm16_sext()`, `norm_imm5_sext()`
- **what it does**: V850/V850E/V850E2/RH850 ISA model. Variant-parameterized instruction sets: each variant rank adds a superset of the previous (V850 < V850E < V850E2 < RH850). IsaModel fields include twodest_mnems (mul/div ops that write two registers), flag_only_mnems (cmp/tst), bit_mem_mnems (set1/clr1/not1/tst1), sysreg_mnems (ldsr/stsr). Explicitly notes V850 operand-order difference (destination last). `norm_imm16_zext()` documents the andi/ori zero-extend difference from RISC-V.
- **inputs/outputs**: `isa_for(Variant) -> IsaModel`; `canon_reg(str) -> Optional[str]`; `norm_imm16_*()` functions
- **scope**: Renesas V850/V850E/V850E2/RH850 (V850E3v5); GCC/CC-RH ABI; 32-bit
- **status**: implemented
- **evidence**: Used by insn_v850.py
- **docs**: Not listed in isa-models.md. **Gap.**
- **limitations**: No FPU register model (V850E2M has FPU); no RH850G4MH-specific extensions beyond core V850E3v5
- **dependencies**: None

## CAP: isa_x86 — x86/x86-64 ISA/ABI Model

- **name**: `AbiModel`, `SyscallModel` dataclasses + `RegInfo`, `Mode`, `Abi` enums + `normalize_mnemonic()`
- **category**: ISA/ABI model
- **paths**: `ablation/analyzers/isa_x86.py`
- **entry point**: `Mode` enum (X86, X64); `Abi` enum (SYSV64, WIN64, CDECL32); `reg_info(name, mode) -> Optional[RegInfo]`; `abi_for(abi) -> AbiModel`; `syscall_model(mode) -> SyscallModel`; `normalize_mnemonic(m) -> Tuple[prefixes, canon]`; mnemonic class frozensets (COPY, ZEXT_COPY, SEXT_COPY, ALU2, ALU1, FLAGS_ONLY, CALL, JMP, RET, SYSCALL, etc.)
- **what it does**: x86/x86-64 ISA model. `_GPR64`/`_GPR32` dicts encode full sub-register aliasing (ah/al/ax/eax/rax with family, low_bit, width). `RegInfo` provides mask computation. Three ABIs: SysV AMD64, Microsoft x64 (shadow_space=32), i386 cdecl (args on stack). Two SyscallModels (x64 and x86 int 0x80). `normalize_mnemonic()` strips AT&T suffixes, canonical condition codes, known AT&T-to-Intel aliases, and REP/LOCK prefix extraction.

- **scope**: IA-32 (x86) and x86-64; SysV AMD64, Microsoft x64, i386 cdecl; SSE/AVX/AVX-512 register names; x87 FP stack; opmask registers k0–k7
- **status**: implemented
- **evidence**: Listed in insn-models.md; used by insn_x86.py
- **docs**: Listed in insn-models.md (partially); isa-models.md does not list isa_x86. **Gap in isa-models.md.**
- **limitations**: AVX-512 zmm0–zmm31 register aliasing present but not fully exploited in taint; no x87 FP stack push/pop depth model
- **dependencies**: None

## CAP: insn_arc — ARC Instruction Model

- **name**: `Insn` dataclass; operand types `Reg`, `Imm`, `Mem`, `RegList`, `Sym`; `make_insn()`, `canonicalize()`, `from_listing()`, `from_objdump()`

- **docs**: Listed in insn-models.md. Note: insn-models.md doc says `Insn` is frozen and uses field name `operands` and `va`; actual code uses `ops` and `address` and `Insn` is **not** frozen. **Doc/code mismatch.**
- **limitations**: No Capstone backend (none exists for ARC); `RegList` for enter/leave only partially handled
- **dependencies**: `isa_arc.py`

## CAP: insn_arm32 — ARM32/Thumb Instruction Model

- **name**: `Insn` dataclass; operand types `Reg`, `Imm`, `Mem`, `RegList`, `Sym`; `make_insn()`, `canonicalize()`, `from_listing()`, `from_objdump()`, `from_capstone()`
- **category**: Instruction model / backend
- **paths**: `ablation/analyzers/insn_arm32.py`
- **entry point**: `make_insn(address, mnemonic, op_str, mode, size) -> Insn`; three backend functions; `literal_address(insn, mem, mode) -> Optional[int]`
- **what it does**: ARM32/Thumb instruction model with UAL parser. Three backends: hand listing, objdump, Capstone. `canonicalize()` normalizes: adr→add, ldr/str sp-relative→pop/push, ldmia sp!/stmdb sp!→pop/push, mov reg shift→shift-mnemonic. `Reg` carries optional shift and subtracted flag. `Mem` carries writeback, post-index, and shift fields. `_attach_literal()` resolves ldr [pc, #n] to the literal value from the word table.
- **inputs/outputs**: UAL text or Capstone detail → `Insn` iterator; `Insn` has `cond`, `sets_flags`, `writeback`, `literal` fields
- **scope**: ARM A32 and Thumb-2 (T32); handles VFP register lists; both objdump and Capstone output
- **status**: implemented
- **evidence**: Three backends tested; literal pool attachment implemented
- **docs**: Only ARC and x86 called out in insn-models.md. **Not explicitly documented.**
- **limitations**: No IT-block tracking (IT blocks parsed but not state-tracked); NEON register lists for vldm/vstm partially handled
- **dependencies**: `isa_arm32.py`, optionally `capstone`

- **dependencies**: `isa_arm64.py`, optionally `capstone`

## CAP: insn_m88k — Motorola MC88100 Instruction Decoder

- **name**: `M88kInsn` dataclass; `M88kDecoder` class; `function_starts()`, `string_refs()`
- **category**: Instruction model / binary decoder
- **paths**: `ablation/analyzers/insn_m88k.py`
- **entry point**: `M88kDecoder(binary)` where binary is `M88kCoffBinary`; `decoder.decode_word(word, va) -> M88kInsn`; `decoder.disassemble_va(start_va, max_insns) -> Iterator[M88kInsn]`; `decoder.disassemble_bytes(data, base_va)`; `decoder.function_starts() -> Set[int]`; `decoder.string_refs() -> Dict[int, int]`
- **what it does**: Pure-Python MC88100 decoder. `M88kInsn` carries: address, mnemonic, op_str (string, not typed operands), raw 32-bit word, is_branch, is_call, is_return, branch_target. `decode_word()` dispatches on opcode field (bits 31:26). `function_starts()` recovers all BSR/BSR.N call targets in .text. `string_refs()` scans ORU+OR pairs for 32-bit constant loads pointing into .data.
- **inputs/outputs**: `M88kCoffBinary` → `M88kInsn` objects; operands are string `op_str`, not typed (unlike all other insn modules)
- **scope**: MC88100 only; requires `coff_m88k_parser` BCS COFF binary
- **status**: implemented (triadic ops partial)
- **evidence**: Validated at 126 function entries, 73 string refs on Lotus moto_gen binary; documented in m88k-decoder.md
- **docs**: m88k-decoder.md is accurate and thorough
- **limitations**: `M88kInsn.op_str` is a plain string — no typed operands (Reg/Imm/Mem). Taint analysis cannot query operands by type without a string parser. Triadic ops (0x3A–0x3C) emit placeholder mnemonics. No CFG builder (`cfg_m88k.py` listed as future work in m88k-decoder.md).
- **dependencies**: `isa_m88k.py`, `ablation.core.coff_m88k_parser`

- **paths**: `ablation/analyzers/insn_mips.py`
- **entry point**: `make_insn(address, mnemonic, op_str, mode, size, code, little, abi) -> Insn`; three backends
- **what it does**: MIPS instruction model. `Insn` carries `code` (raw bytes) and `little` endian flag; `insn.word` property reconstructs the 32-bit instruction word. `canonicalize()` uses the raw word to disambiguate `move`: in MIPS64, addu-form move (funct=0x21) sign-extends, so it is expanded to `addu rd, rs, $0` for correct taint. Also canonicalizes: jalr (1-op → 2-op with $31), beqz/bnez → beq/bne, b → beq $0,$0, li → addiu, negu/dnegu → subu/dsubu, not → nor, sll $0 → nop.
- **inputs/outputs**: Text or Capstone → `Insn` iterator; `Insn.word` for encoding-dependent canonicalization
- **scope**: MIPS32/64; o32 and n64 ABIs; big- and little-endian; objdump nop-elision re-insertion
- **status**: implemented
- **evidence**: from_objdump handles elided nop runs; from_capstone maps Capstone register names through o32 table
- **docs**: Not documented in insn-models.md. **Gap.**
- **limitations**: MIPS16e/microMIPS not handled; no delay-slot tracking in `Insn` (has_delay_slot is in isa_mips.py but not applied here)
- **dependencies**: `isa_mips.py`, optionally `capstone`

## CAP: insn_ppc — PowerPC Instruction Model

- **name**: `Insn` dataclass; operand types `Reg`, `Imm`, `Mem`, `Sym`; `make_insn()`, `canonicalize()`, `from_listing()`, `from_objdump()`, `from_capstone()`
- **category**: Instruction model / backend
- **paths**: `ablation/analyzers/insn_ppc.py`
- **entry point**: `make_insn(address, mnemonic, op_str, mode, size) -> Insn`; `canonicalize(insn, mode) -> Insn`; three backends
- **what it does**: PowerPC instruction model. `canonicalize()` is the most extensive of any ISA module: expands all rotate/shift extended mnemonics (slwi→rlwinm, srdi→rldicl, extrwi→rlwinm, etc.) with computed mb/me/sh fields; normalizes sub→subf with swapped operands, subi/subis→addi/addis with negated immediate, addi r0→li, or rs,rs→mr, mtspr/mfspr with SPR table, crclr/crset/cr-logic→crlogic; bcc-family to unified bcclr/bccctr/bcc forms. `Insn.record` flag tracks Rc=1.
- **inputs/outputs**: Text or Capstone → `Insn` iterator; `Insn.record` for CR0-update tracking
- **scope**: PPC32/64; SysV32/ELFv1/ELFv2; big- and little-endian; Altivec and VSX mnemonics via Capstone
- **status**: implemented
- **evidence**: Capstone backend handles X-form load/store index and cache ops specially
- **docs**: Not explicitly documented in insn-models.md. **Gap** (only ARC and x86 called out).
- **limitations**: `operand_kinds()` fallback to `["i"]` for unknown mnemonics may misparse some ops
- **dependencies**: `isa_ppc.py`, optionally `capstone`

## CAP: insn_riscv — RISC-V Instruction Model

- **name**: `Insn` dataclass; operand types `Reg`, `Imm`, `Mem`, `Sym`; `make_insn()`, `jal_link_and_target()`, `jalr_link_and_base()`, `from_listing()`, `from_objdump()`, `from_capstone()`
- **category**: Instruction model / backend
- **paths**: `ablation/analyzers/insn_riscv.py`
- **entry point**: `make_insn(address, mnemonic, op_str, size) -> Insn`; three backends; `jal_link_and_target(insn) -> (str, Optional[int])`; `jalr_link_and_base(insn) -> (str, Optional[str], int)`
- **what it does**: RISC-V instruction model. No `canonicalize()` — normalization is handled by isa_riscv.py mnemonic classification. C-extension (compressed) instructions inferred from `c.` prefix for size=2. `jal_link_and_target()` and `jalr_link_and_base()` are CFG helpers that decode all jal/jalr variants (j, c.j, c.jal, ret, jr, c.jr, c.jalr, jalr 1-/2-/3-op) to `(link_reg, target)` tuples.

- **status**: implemented
- **evidence**: CFG helpers cover all known jal/jalr forms
- **docs**: Not documented in insn-models.md. **Gap.**
- **limitations**: No `canonicalize()` (pseudo-op expansion is not done at Insn level, relies on isa_riscv IsaModel mnemonic sets); no A/F/D extension handling in operands
- **dependencies**: `isa_riscv.py`, optionally `capstone`

## CAP: insn_v850 — V850/RH850 Instruction Model

- **name**: `Insn` dataclass; operand types `Reg`, `Imm`, `Mem`, `RegList`, `Sym`; `make_insn()`, `jarl_link_and_target()`, `jmp_base()`, `from_objdump()`, `from_listing()`, `from_v850_frames()`
- **category**: Instruction model / backend
- **paths**: `ablation/analyzers/insn_v850.py`
- **entry point**: `make_insn(address, mnemonic, op_str, size) -> Insn`; two text backends plus `from_v850_frames(frames)`; `jarl_link_and_target(insn) -> (link_reg, target_or_None, indirect_base_or_None)`; `jmp_base(insn) -> Optional[str]`
- **what it does**: V850/RH850 instruction model. `Mem` uses V850 disp[base] syntax. `RegList` handles prepare/dispose and pushsp/popsp. `from_listing()` infers instruction size: 16-bit short forms from `_SHORT` set, 48-bit for mov with imm32, 32-bit default. `jarl_link_and_target()` handles both direct (offset) and indirect ([r6]) jarl forms for CFG building.
- **inputs/outputs**: Text or frames → `Insn` iterator; CFG helpers for jarl/jmp
- **scope**: V850 through RH850; two text backends + frame-based input
- **status**: implemented
- **evidence**: Three-backend support; `from_v850_frames` for integration with V850 decoder
- **docs**: Not documented in insn-models.md. **Gap.**
- **limitations**: No `canonicalize()`; `from_listing` size inference for `mov` checks first operand only (may missize in edge cases)
- **dependencies**: `isa_v850.py`

## CAP: insn_x86 — x86/x86-64 Instruction Model

- **name**: `Insn` dataclass; operand types `Reg`, `Imm`, `Mem`, `Sym`; `make_insn()`, `att_to_intel()`, `rip_relative_target()`, `from_listing()`, `from_objdump()`, `from_capstone()`
- **category**: Instruction model / backend
- **paths**: `ablation/analyzers/insn_x86.py`
- **entry point**: `make_insn(address, mnemonic, op_str, mode, size) -> Insn`; `att_to_intel(mnemonic, op_str) -> Tuple[str, str]`; `rip_relative_target(insn, mem, mode) -> Optional[int]`; three backends
- **what it does**: x86/x86-64 instruction model. `Insn.prefixes` tuple carries REP/LOCK/segment prefixes separately from mnemonic. `Mem` carries full SIB (base, index, scale, disp) plus size and segment. `make_insn()` performs: sign-extension of unsigned-rendered immediates (e.g. `and rsp, 0xfffffffffffffff0` → -16), register-width propagation to adjacent unsized memory operand, string-op folding (movs/stos/etc → operand-stripped form). `att_to_intel()` is a full AT&T-to-Intel converter: reverses operand order, strips %, $, maps size suffixes and AT&T mnemonic aliases. `rip_relative_target()` computes absolute address from rip-relative memory operands.
- **inputs/outputs**: Intel listing, AT&T objdump, or Capstone → `Insn` iterator; `att_to_intel()` is a standalone converter
- **scope**: IA-32 and x86-64; Intel and AT&T syntax; SSE/AVX/AVX-512; x87; opmask; segment regs
- **status**: implemented
- **evidence**: Listed in insn-models.md; three backends; AT&T conversion tested
- **docs**: Listed in insn-models.md (accurately). insn-models.md doc says `Insn` is frozen and uses `va`/`operands` field names — actual code uses mutable `Insn` with `address`/`ops`. **Doc/code mismatch** (same issue as insn_arc).
- **limitations**: No CFG-building hook in this module (CFG is in cfg_builder.py); `Insn` is not frozen despite doc claim
- **dependencies**: `isa_x86.py`, optionally `capstone`

## Reference Doc Coverage Gaps

### isa-models.md

The document only lists 4 ISA modules: `isa_arc`, `isa_arm32`, `isa_arm64`, `isa_ppc`. The following 6 ISA modules are missing from the doc entirely:

- `isa_loongarch64.py`
- `isa_m88k.py`
- `isa_mips.py`
- `isa_riscv.py`
- `isa_v850.py`
- `isa_x86.py`

### insn-models.md

The document only describes 2 insn modules: `insn_arc` and `insn_x86`. The following 8 are missing:

- `insn_arm32.py`
- `insn_arm64.py`
- `insn_loongarch64.py`
- `insn_m88k.py`
- `insn_mips.py`
- `insn_ppc.py`
- `insn_riscv.py`
- `insn_v850.py`

### insn-models.md dataclass contract mismatch

The doc specifies `Insn` as `frozen=True` with fields `va` and `operands`. All actual `insn_*.py` implementations use a **mutable** `@dataclass` (not frozen) with fields `address` and `ops`. Any code generated from the reference doc using `insn.va` or `insn.operands` will fail at runtime.

### m88k-decoder.md

Accurate and complete. Only gap: `M88kInsn.op_str` is a plain string (not typed operands) — the doc does not warn that taint analysis requires a string parser, unlike all other insn modules.

## Structural Observations

1. **No taint propagation logic in isa_*.py or insn_*.py.** These are pure data/parsing layers. Taint logic lives in separate taint_tracker_*.py files that import these modules.

2. **No CFG-building hooks in insn_*.py.** CFG building is in separate cfg_*.py files. The exception is that `jal_link_and_target()` and `jalr_link_and_base()` in `insn_riscv.py`, and `jarl_link_and_target()` / `jmp_base()` in `insn_v850.py` are CFG helpers embedded in the insn module.

3. **Sink/Source/Copy/Load/Store classification lives in isa_*.py** (as mnemonic frozensets: LOAD, STORE, COPY, CALL, RET, etc.), not in insn_*.py.

4. **M88K is architecturally different** from all other insn modules: `M88kInsn.op_str` is a string, not typed operands. This is the only module without a typed operand model.

5. **insn_loongarch64.py has no Mem type** — a deliberate design choice documented in the module. Load/store operands stay as `[Reg, Reg, Imm]`. This is unique among all ISA modules.

6. **AbiModel dataclass presence varies**: ARM32, ARC, and LoongArch64 do not use an AbiModel dataclass; PPC, MIPS, x86 do; AArch64/RISC-V/V850 use an IsaModel dataclass (mnemonic classification) but no separate AbiModel.
