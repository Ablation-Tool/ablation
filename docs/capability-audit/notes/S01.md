## SWEEP: base_sweep

- **name**: base_sweep.py
- **category**: Sweep
- **paths**: sweeps/base_sweep.py
- **entry point**: `python3 sweeps/base_sweep.py /path/to/binary [--start HEX] [--end HEX] [--top N] [--vendor STR] [--product STR] [--version STR] [--no-xref] [--report PATH] [--register THRESHOLD]`; `main()` → `sweep()` → `extract_functions()`
- **what it does**: Encodes all x86-64 ELF functions via `describe_function`, runs 8 base `VULN_PROFILES` plus prior confirmed findings from `FindingRegistry` as semantic similarity queries using `SentenceTransformer all-MiniLM-L6-v2`. Augments function descriptions with string xrefs and caller context from `XRefGraph`. Runs intraprocedural and interprocedural (depth-4) taint analysis via `TaintTracker`. Registers high-scoring candidates interactively into `FindingRegistry` when `--register` flag is set.
- **target formats**: Stripped x86-64 ELF (Linux, firmware). Prologue scan uses `push rbp; mov rbp,rsp` (0x55 0x48 0x89) as primary function start; `XRefGraph.eh_frame` func_starts as fallback when prologue coverage is sparse.
- **analyzers chained**:
  - `SemanticSearcher` (via `describe_function` + `model.encode`; sentence-transformers wrapper, not the class directly)
  - `FindingRegistry` (prior queries + registration)
  - `XRefGraph` (string xrefs + call graph; `XRefGraph.from_path`)
  - `TaintTracker` (intraprocedural, `taint_tracker_x86`)
  - `InterproceduralPath` (depth-4 BFS, `taint_tracker_x86`)
  - `report_generator.generate_report` (optional, when `--report` or `--vendor/--product` set)
- **inputs**: `binary` (positional path), optional `--start`/`--end` hex VAs, `--top` int, `--vendor`, `--product`, `--version`, `--no-xref`, `--report`, `--register` float threshold
- **outputs**: stdout ranked candidates per vuln class; optional markdown report at `--report` path or auto-named `reports/sweep_<slug>_<ts>.md`
- **status**: implemented
- **evidence**: no dedicated test file found in sweeps/ or tests/ referencing base_sweep directly; called as library by fortinet_sweep.py (_build_all_profiles, extract_functions, _find_prologue_starts)
- **docs**: docs/workflows/vuln-hunting.md (Phase 2 matches pipeline); no reference-module doc for base_sweep itself
- **limitations**: x86-64 only for prologue scan; `scan_start` default `0x200000` hardcoded — must be overridden for non-standard load addresses; FPO functions missed without XRefGraph eh_frame; `SinkArgClassifier` not called (fortinet_sweep.py adds that in Phase 3); taint tracker is ELF-only
- **dependencies**: capstone, sentence-transformers (all-MiniLM-L6-v2), numpy, lief (via XRefGraph), ablation package

## SWEEP: fortinet_sweep

- **name**: fortinet_sweep.py
- **category**: Sweep
- **paths**: sweeps/fortinet_sweep.py
- **entry point**: `python3 sweeps/fortinet_sweep.py <target|dir> [--vendor STR] [--product STR] [--version STR] [--top N] [--max-funcs N] [--report PATH] [--no-vendor-profile]`; `main()` → `_sweep_one()` (single) or `sweep_directory()` (dir)
- **what it does**: Four-phase FortiOS-specific sweep. Phase 0 (directory mode): `batch_plt_intersect` PLT triage to skip binaries with no exec-class sinks. Phase 1: `XRefGraph` + semantic sweep using 8 base + 8 `FORTIOS_PROFILES` + registry priors; falls back to `eh_frame` func_starts when `-fomit-frame-pointer` prologues are absent (common in FortiOS). Phase 2: arch-routed taint analysis (x86-64 full interprocedural depth-4, ARM32 intraprocedural, ARM64 intraprocedural, PPC32/PPC64 with interprocedural). Phase 3 (x86-64 only): `SinkArgClassifier` + `VendorProfile("fortinet")` + `SanitizerDetector` to classify exec sink argument provenance (RODATA_CONST / SNPRINTF_RODATA / ARG_PROPAGATED / UNKNOWN).
- **target formats**: ELF binaries of any arch (x86-64, ARM32, ARM64, PPC32, PPC64, MIPS); directory of ELFs from FortiOS firmware extraction
- **analyzers chained** (in execution order):
  1. `batch_plt_intersect` (triage phase 0, directory mode)
  2. `XRefGraph.from_path` (phase 1, all arches)
  3. `FindingRegistry` (phase 1, prior queries + embedding build)
  4. `describe_function` (phase 1, per-function description)
  5. `TaintTracker` (phase 2, x86-64; from `ablation.analyzers`)
  6. `ARM32TaintTracker` (phase 2, ARM32; from `ablation.analyzers`)
  7. `ARM64TaintTracker` (phase 2, ARM64; from `ablation.analyzers`)
  8. `PPC64TaintTracker` (phase 2, PPC64; from `ablation.analyzers`)
  9. `PPC32TaintTracker` (phase 2, PPC32; from `ablation.analyzers`)
  10. `SinkArgClassifier.from_path` (phase 3, x86-64 only; from `ablation.analyzers`)
  11. `VendorProfile.from_vendor("fortinet")` (phase 3, x86-64 only; from `ablation.analyzers`)
  12. `SanitizerDetector` (phase 3, x86-64 only; from `ablation.analyzers`)
- **inputs**: `target` (positional: path to ELF or directory), `--vendor` (default "fortinet"), `--product`, `--version`, `--top`, `--max-funcs` (skip semantic sweep for large binaries), `--report`, `--no-vendor-profile`
- **outputs**: `reports/sweep_fortinet_<product>_<version>_<ts>.md` (or `--report` path); per-binary sections with semantic hits, taint direct hits, interprocedural chains, SinkArgClassifier report, SanitizerDetector report
- **status**: implemented
- **evidence**: CLAUDE.md explicitly names `fortinet_sweep.py` as the pattern/template for semantic sweep workflow; referenced in docs/workflows/fortinet-firmware.md
- **docs**: docs/workflows/fortinet-firmware.md (Layer 3); orphan_docs has "fortinet-multi-phase-directory-sweeps" (not in docs/workflows/)
- **limitations**: SinkArgClassifier/VendorProfile/SanitizerDetector (Phase 3) run on x86-64 only; ARM32/ARM64 taint is intraprocedural only (no depth-4 BFS); MIPS32/MIPS64 taint not dispatched (only PPC32/PPC64); `_detect_arch` uses lief string comparison which is version-sensitive; `--max-funcs` causes semantic sweep skip on large binaries (taint + PLT triage still run)
- **dependencies**: capstone, sentence-transformers, numpy, lief, ablation package

## SWEEP: android_sweep

- **name**: android_sweep.py
- **category**: Sweep
- **paths**: sweeps/android_sweep.py
- **entry point**: `python3 sweeps/android_sweep.py /path/to/app.apk [--native-dir DIR]`; `run_sweep()` → `APKParser.from_path()` + `DexAnalyzer(apk).scan()` + `_native_lib_findings()`
- **what it does**: Three-phase Android APK sweep. (1) Parses AndroidManifest.xml for permissions, exported components, SDK versions. (2) Scans all classes*.dex files via `DexAnalyzer` for dangerous API calls, hardcoded secrets, cleartext URLs, exported component misuse. (3) Inventories native .so libraries for ELF security properties (NX, RELRO, stack canary, FORTIFY) using inline struct parsing (ELF32 LE assumed), flags EOL OpenSSL 1.1, V8 engine presence, PLT hooking frameworks (shadowhook/bytehook), on-device ML libraries (ncnn/MediaPipe/TFLite), BLE libraries, and optionally extracts priority security-critical .so files to `--native-dir` for subsequent ELF sweep.
- **target formats**: Android APK (.apk); armeabi-v7a native .so (ELF32 LE ARM32)
- **analyzers chained**:
  - `APKParser` (from `ablation.core.apk_parser`)
  - `DexAnalyzer` (from `ablation.analyzers.dex_analyzer`)
  - `_elf_security_props` (inline — no external analyzer class)
- **inputs**: `apk` (positional path), `--native-dir` (optional extraction directory for security-critical .so files)
- **outputs**: stdout: manifest summary, DEX stats, `DexAnalyzer.report(findings)`, next-steps list of native RE targets; extracted .so files under `--native-dir` if specified
- **status**: implemented
- **evidence**: no dedicated test file found; `_SECURITY_CRITICAL_LIBS` set hardcoded with Tuya/Thing app library names suggesting specific engagement origin
- **docs**: docs/guide-tool-selection.md (Android APK row absent — gap); A11 unit_docs has "android-apk-analysis" (DexAnalyzer reference, not sweep)
- **limitations**: ELF security property check is ELF32 LE only (armeabi-v7a); arm64-v8a .so files (ELF64) not parsed by `_elf_security_props`; no semantic BERT sweep of APK content (only pattern-based DexAnalyzer); hardcoded `_SECURITY_CRITICAL_LIBS` is Tuya-specific; `--native-dir` extracts only the hardcoded priority set, not all .so; DEX taint analysis depth limited to DexAnalyzer's built-in scan patterns
- **dependencies**: capstone (not used directly in android_sweep — only ablation.core.apk_parser + ablation.analyzers.dex_analyzer), standard library struct/pathlib

## SWEEP: pe_sweep

- **name**: pe_sweep.py
- **category**: Sweep
- **paths**: sweeps/pe_sweep.py
- **entry point**: `python3 sweeps/pe_sweep.py <target|dir> [--vendor STR] [--product STR] [--version STR] [--top N] [--report PATH]`; `main()` → `_sweep_pe_one()` or `sweep_directory_pe()`
- **what it does**: Windows PE (i386 and AMD64) semantic vulnerability sweep adapted from fortinet_sweep.py. Builds Import Address Table (IAT) from lief instead of PLT. Detects function starts via prologue scan (MSVC/GCC patterns for both x86-32 and AMD64) plus FPO recovery via `E8 rel32` call-target scanning. Runs semantic sweep with 8 base + 8 `PE_WIN_PROFILES` (QuickTime/Windows-specific patterns). Also runs deterministic `FirmwareAuthBypassFinding` check (GAP-015): detects PE firmware flashers that import firmware-update APIs (hidapi.dll, IAP functions) but no code-signing imports (WinVerifyTrust, Crypt*). String context from `.rdata` section (falls back to `.data` for Borland VCL binaries — GAP-016). Taint analysis and SinkArgClassifier skipped (both ELF-only).
- **target formats**: Windows PE32 (i386) and PE32+ (AMD64) — .exe, .dll, .ocx, .ax. ARM and ARM64 PE are detected but skipped with warning.
- **analyzers chained**:
  - `describe_function` (from `ablation.analyzers`)
  - `FindingRegistry` (from `ablation.analyzers`, prior queries)
  - `_check_firmware_auth_bypass` (inline deterministic check — no external class)
- **inputs**: `target` (positional: PE file or directory), `--vendor`, `--product`, `--version`, `--top`, `--report`
- **outputs**: `reports/sweep_pe_<vendor>_<product>_<version>_<ts>.md`; sections per binary with arch/IAT size/function count, optional FIRMWARE_AUTH_BYPASS deterministic finding, semantic sweep hits
- **status**: implemented
- **evidence**: A07 unit_docs has "pe-sweep" and "pe-sink-classifier" confirming this is a recognized unit; doc-unit-mapping.json unit_files has `pe_sink_classifier` in A07
- **docs**: A07 orphan_docs has "pe-sweep"; docs/guide-tool-selection.md Windows PE row references pe_sweep.py
- **limitations**: No taint tracker (all taint trackers are ELF-only); XRefGraph not used (ELF-only); SinkArgClassifier not called; ARM/ARM64 PE skipped; packed/virtual-only PE (.text file_offset=0) skipped; FPO recovery uses i386 E8 scan only (same opcode for AMD64 — works but label used for both)
- **dependencies**: lief, capstone, sentence-transformers, numpy, ablation package

## SWEEP: ti_sweep

- **name**: ti_sweep.py
- **category**: Sweep
- **paths**: sweeps/ti_sweep.py
- **entry point**: `python3 sweeps/ti_sweep.py <tirex_dir|zip|binary> [--no-taint] [--semantic] [--filter STR] [--product STR] [--version STR]`; `main()` → `sweep_directory()` (dir of zips) or `sweep_package()` (single zip/dir/file)
- **what it does**: Four-phase Texas Instruments SDK firmware sweep targeting TIREX package directories (138 zip archives, ~23 GB). Phase 1 NNC: `TiNNCScanner` on all COFF/AR + ELF files (fast symbol-table-only scan for neural network compiler artifacts); handles ELF AR archives from tiarmclang (LLVM-based). Phase 2 Taint: arch-routed `ARM32TaintTracker` (Thumb), `ARM64TaintTracker`, `RISCV32TaintTracker` on PLT-passing ELF files; parallelized with ThreadPoolExecutor. Phase 3 C28x: `TiCoffLoader` to enumerate C_UEXT weak symbols + `EcuSecurityAccessScanner` on flat .bin images for static UDS SecurityAccess seeds. Phase 4 Crypto: `HashAlgoDiscriminator` (ARM32 Thumb ELFs only; first 1 MB). Optional semantic sweep via `BinaryContext` + `SemanticSearcher` (disabled by default; `--semantic` flag).
- **target formats**: TI COFF2/AR (.a, .lib) from TI C28x toolchain; ARM Thumb ELF (.out) from tiarmclang; ARM64 ELF; RISC-V 32 ELF; flat binary (.bin) for ECU ROM images; zip packages (TIREX format with optional single nested zip)
- **analyzers chained**:
  - `TiNNCScanner` (phase 1; from `ablation.analyzers.ti_nnc_scanner`)
  - `ARM32TaintTracker.from_path(path, thumb=True)` (phase 2; from `ablation.analyzers.taint_tracker_arm32`)
  - `ARM64TaintTracker.from_path_full` (phase 2; from `ablation.analyzers.taint_tracker_arm64`)
  - `RISCV32TaintTracker.from_path` (phase 2; from `ablation.analyzers.taint_tracker_riscv32`)
  - `TiCoffLoader.from_path` (phase 3; from `ablation.analyzers.ti_coff_loader`)
  - `EcuC28xDecoder` (phase 3; from `ablation.analyzers.ecu_c28x_decoder`)
  - `EcuSecurityAccessScanner` (phase 3; from `ablation.analyzers.ecu_security_access_scanner`)
  - `HashAlgoDiscriminator` (phase 4; from `ablation.analyzers.crypto_pattern_detector`)
  - `BinaryContext.load_or_build` (optional semantic; from `ablation.analyzers.binary_context`)
  - `SemanticSearcher.from_context` (optional semantic; from `ablation.analyzers.semantic_search`)
  - `PlatformDetect` (from `ablation.core.platform_detect`; imported but used only in phase 2 comment)
- **inputs**: `input` (positional: TIREX dir, .zip package, or binary file), `--no-taint`, `--semantic` (off by default), `--filter` (package name substring), `--product`, `--version`
- **outputs**: per-package `reports/sweep_ti_<pkg>_<ts>.md` (markdown table: ID, severity, binary, title, phase); master `reports/sweep_ti_master_<ts>.md` across all packages
- **status**: implemented
- **evidence**: A10 unit_docs has "ti-sweep" and "ti-nnc-scanner"; doc-unit-mapping.json has `ti_coff_loader` and `ti_nnc_scanner` in A10 unit_files
- **docs**: A10 unit_docs: "ti-sweep", "ti-sdk-package-sweeping", "ti-coff-loader", "ti-nnc-scanner"
- **limitations**: Semantic sweep disabled by default (slow; `--semantic` required); EcuC28xDecoder C28x COFF section extraction noted as incomplete in source comment ("For now: enumerate C_UEXT symbols" — partial); MIPS and PPC not dispatched in phase 2 taint; phase 3 C28x weak symbol scan is conservative (top 10 symbols only); `ARM64TaintTracker.from_path_full` method name must exist (not verified against module); `RISCV32TaintTracker` imported from `taint_tracker_riscv32` — present in A05 unit_files as `taint_tracker_riscv32`
- **dependencies**: zipfile, concurrent.futures.ThreadPoolExecutor, lief, ablation package (no sentence-transformers unless `--semantic`)

## SWEEP: corpus_miner

- **what it does**: Cross-target finding corpus miner. Reads all `*_re.py` modules under `~/ablation/re/` using Python `ast.parse`, extracts `FINDINGS` dict entries with `status == 'CONFIRMED'`, normalizes CWE tags (explicit or inferred from title via `_TITLE_CWE_MAP`), and produces: (1) `CorpusEntry` list — structured record per confirmed finding; (2) CWE frequency table; (3) coverage gaps — high-frequency CWEs with no ablation scanner; (4) cross-target patterns — same CWE in ≥2 vendors → module candidates. Implements the ablation flywheel: confirmed findings feed back into tooling priorities.
- **target formats**: N/A (reads Python source files, not binaries)
- **analyzers chained**: none (pure Python AST parsing; no ablation.analyzers classes called)
- **inputs**: `--re-dir` (default ~/ablation/re/), `--min-count` (default 2), `--min-vendors` (default 2), `--json` (machine-readable), `--out` (output file path)
- **outputs**: stdout or `--out` file: text report with severity distribution, vendor breakdown, CWE frequency table, coverage gaps, cross-target patterns; or JSON with entries/gaps/patterns arrays
- **status**: implemented
- **evidence**: A12 unit_docs has "finding-corpus-mining" matching this module's purpose
- **docs**: A12 unit_docs: "finding-corpus-mining"; `_CWE_COVERAGE` dict inline documents which ablation modules cover each CWE class
- **limitations**: Requires `FINDINGS` dict with `status == 'CONFIRMED'` in re/*.py files — empty re/ directory produces no output; CWE inference from title is pattern-matched (may miss novel finding titles); `_CWE_COVERAGE` map is a static snapshot — may not reflect current module state; does not call any analyzer classes, so it cannot validate that referenced modules exist or are functional
- **dependencies**: Python standard library only (ast, json, re, collections, dataclasses, pathlib)

- **status**: implemented

## SWEEP: win16_le_vxd_sweep

- **name**: win16_le_vxd_sweep.py
- **category**: Sweep
- **paths**: sweeps/win16_le_vxd_sweep.py
- **entry point**: `python3 sweeps/win16_le_vxd_sweep.py <target|dir> --vendor STR --product STR --version STR [--top-k N] [--threshold FLOAT] [--out-dir PATH]`; `main()` → `_sweep_le_one()` → `_extract_functions_le(LEBinary)` → `_semantic_sweep_le()`
- **what it does**: Windows 3.x LE (Linear Executable) VxD ring-0 semantic sweep. Fills GAP-F (no prior Ablation loader for LE/VxD format). Pure Python `LEBinary` class parses LE header, object page table (big-endian 3-byte page numbers), assembles flat code bytes from pages, detects VxD DDB (Device Descriptor Block) to name entry-point functions. Resolves VMM service calls via INT 20h + DWORD service ID from a 100+ entry `_VMM_SERVICES` table (VMM, VPICD, VTDI). Disassembles with Capstone CS_MODE_32. Semantic sweep with base + NE + 5 VxD-specific `VXD_LE_PROFILES` (ring-0 heap overflow, NetBIOS name overflow, heap allocation integer overflow, TOCTOU on V86 parameter, ring-0 format string).
- **target formats**: Windows 3.x LE VxD binaries (.386, .vxd, .drv, .sys) — requires MZ stub + LE magic at offset 0x3C
- **analyzers chained**:
  - `describe_function` (from `ablation.analyzers`)
  - `FindingRegistry` (from `ablation.analyzers`)
  - `WIN16_NE_PROFILES` (imported from `sweeps.win16_ne_sweep`)
  - `VULN_PROFILES` (imported from `sweeps.base_sweep`)
- **inputs**: `target` (positional: .386/.vxd file or directory), `--vendor`, `--product`, `--version` (all required), `--top-k` (default 5), `--threshold` (default 0.30), `--out-dir` (default reports/)
- **outputs**: `reports/sweep_le_<vendor>_<product>_<version>_<ts>.md`; per-binary: LE header metadata, DDB info (device name, SDK ver, entry point VAs), semantic sweep hits above threshold
- **status**: implemented
- **evidence**: A09 unit_docs has "windows-le-vxd" and "windows-16-bit-ne"; orphan_docs has "win16-le-vxd-sweep"
- **docs**: orphan_docs: "win16-le-vxd-sweep" (referenced in mapping but no workflow guide in docs/workflows/); A09 unit_docs: "windows-le-vxd"
- **limitations**: No taint tracker (VxD ring-0 taint not implemented); `_VMM_SERVICES` table incomplete (covers VMM, VPICD, VTDI only — other VxD device IDs return generic `VxD_DevXXXX!svc_XXXX`); `max_bytes=512` per function is smaller than base_sweep (2048) and pe_sweep (2048) — may miss longer functions; DDB scan limited to three pattern bytes; `_find_prologue_starts_x86_32` here adds `53 55 89` and `c8 ?? ?? 00` patterns not in pe_sweep (correct — VxD prologues vary)
- **dependencies**: capstone, sentence-transformers, numpy, ablation package; no lief (pure Python LE parsing)

## SWEEP: win16_mz_dos_sweep

- **name**: win16_mz_dos_sweep.py
- **category**: Sweep
- **paths**: sweeps/win16_mz_dos_sweep.py
- **entry point**: `python3 sweeps/win16_mz_dos_sweep.py <paths...> [--threshold FLOAT] [--vendor STR] [--product STR] [--version STR]`; `main()` → `sweep(path)` → `_score_function(insns)` per function
- **what it does**: Security sweep for 16-bit real-mode MS-DOS MZ executables. Fills GAP-G (no prior Ablation loader for real-mode MZ DOS). Pure Python `MZBinary` class parses MZ header, relocation table, and assembles code bytes. Function starts recovered via entry point + `E8 rel16` NEAR CALL targets + prologue scan (`push bp; mov bp,sp`). Disassembles with Capstone CS_MODE_16. Scores each function via `_score_function()` against 3 DOS-specific heuristic profiles: `dos_unbounded_copy` (rep movs without CX bounds check), `dos_int21_recv_path` (INT 21h AH loaded from memory), `dos_fixed_stack_alloc` (sub sp, N where N > 0x100). Does NOT use BERT/sentence-transformers — uses rule-based scoring (0.0–1.0).
- **target formats**: Real-mode MS-DOS MZ executables (.exe, .com-like with MZ magic 'MZ' or 'ZM'); 16-bit large-model with multiple code segments
- **analyzers chained**: none (no ablation.analyzers classes called; capstone only)
- **inputs**: `paths` (one or more positional file paths), `--threshold` (default 0.30), `--vendor`, `--product`, `--version`
- **outputs**: stdout markdown report; `reports/sweep_mz_<vendor>_<product>_<version>_<ts>.md`; per-binary: function count, hit count, scored function offsets
- **status**: implemented
- **evidence**: orphan_docs has "win16-mz-dos-sweep"; A09 unit_docs has "ms-dos-mz" in orphan_docs (not in A09 explicitly)
- **docs**: orphan_docs: "win16-mz-dos-sweep", "ms-dos-mz"
- **limitations**: No BERT semantic sweep — heuristic scoring only; no `FindingRegistry` integration; no string xref context; `E8 rel16` target wraps at 0xFFFF (modulo semantics — may produce spurious targets near segment boundaries); `dos_unbounded_copy` score is 0.55 flat (no graduated scoring); no far call (0x9A) target recovery; relocation table parsed but segment bases not used for call resolution; single-segment assumption for call target range
- **dependencies**: capstone only; standard library (struct, dataclasses, pathlib)

## SWEEP: win16_ne_sweep

- **name**: win16_ne_sweep.py
- **category**: Sweep
- **paths**: sweeps/win16_ne_sweep.py
- **entry point**: `python3 sweeps/win16_ne_sweep.py <target.exe|.dll|.qtc|.x16> --vendor STR --product STR --version STR [--top-k N] [--threshold FLOAT]`; `main()` → `_sweep_ne_one()` → `_extract_functions_ne(NEBinary)` → `_semantic_sweep_ne()`
- **what it does**: Win16 NE (New Executable) binary semantic sweep adapted from pe_sweep.py. Pure Python `NEBinary` class parses NE header, segment table, module reference table, imported names table. Per-segment relocation records parsed to build `{source_offset: 'MODULE!FuncName'}` import maps. Resolves Win16 API ordinals via 4 lookup tables (KERNEL 202 entries, USER 315 entries, GDI 122 entries, SHELL 20 entries). Disassembles with Capstone CS_MODE_16. Function starts via prologue + NEAR call target recovery. Semantic sweep with 8 base + 8 `WIN16_NE_PROFILES` (lstrcpy overflow, GlobalAlloc overflow, GetDlgItemText overflow, OpenFile path overflow, WinExec injection, WriteProfileString injection, wsprintf format string, resource overflow).
- **target formats**: Win16 NE executables (.exe, .dll, .qtc, .x16) — requires MZ stub + NE magic; lief not used
- **analyzers chained**:
  - `describe_function` (from `ablation.analyzers`)
  - `FindingRegistry` (from `ablation.analyzers`)
  - `VULN_PROFILES` (imported from `sweeps.base_sweep`)
- **inputs**: `target` (positional: NE binary path), `--vendor`, `--product`, `--version` (all required), `--top-k` (default 5), `--threshold` (default 0.30)
- **outputs**: `reports/sweep_ne_<vendor>_<product>_<version>_<ts>.md`; per-binary: segment count, function count, import module list, semantic hits per profile above threshold
- **status**: implemented
- **evidence**: A09 unit_docs has "windows-16-bit-ne" and "ne-format-parser"; doc-unit-mapping.json unit_files has `ne_format_parser` in A09; win16_le_vxd_sweep.py imports `WIN16_NE_PROFILES` from this module
- **docs**: A09 unit_docs: "windows-16-bit-ne", "ne-format-parser"; orphan_docs: "win16-ne-sweep"
- **limitations**: Single-binary mode only (no directory scan — only win16_le_vxd_sweep.py has directory mode for NE); no taint tracker; `_find_near_call_targets_x86_16` uses modulo 0xFFFF — same boundary concern as win16_mz_dos_sweep; FAR CALL (0x9A) resolution tries `call_file_off + 1 - seg_file_off` and `call_file_off - seg_file_off` in reloc map (ambiguous for some target types); `max_bytes=512` per function; no string ref extraction from DS in 16-bit mode (explicitly noted as missing in source)

## Cross-cutting observations

1. **BERT model**: All semantic sweeps (base, fortinet, pe, win16_ne, win16_le_vxd) use `sentence-transformers/all-MiniLM-L6-v2`. win16_mz_dos_sweep.py is the sole exception — it uses heuristic rule scoring, not BERT.

2. **Profile inheritance chain**: win16_le_vxd_sweep imports WIN16_NE_PROFILES from win16_ne_sweep; both import VULN_PROFILES from base_sweep. Profile counts: base=8, NE=8+8=16, LE=8+8+5=21, PE=8+8=16, Fortinet=8+8=16 (+ registry priors at runtime).

3. **Taint tracker coverage by sweep**:
   - base_sweep.py: x86-64 full (intra + inter depth-4)
   - fortinet_sweep.py: x86-64 full, ARM32 intra, ARM64 intra, PPC32/PPC64 with inter; MIPS not dispatched
   - ti_sweep.py: ARM32 Thumb inter, ARM64 inter, RISCV32 inter
   - pe_sweep.py: none (ELF-only)
   - win16_*: none
   - android_sweep.py: none at sweep level (DexAnalyzer only)

4. **Legacy `modules.*` import path**: go-binaries.md (`modules.go_garble_re`), cross-version.md (`modules.structural_sim`), and crypto.md (`modules.crypto_audit`) all use a `modules.` prefix that does not appear in ablation package layout. These may be legacy paths from a prior repo layout. Classes exist (go_garble_re is in A08 orphan_docs "go-garble-re") but import paths may not resolve under current package.

5. **SinkArgClassifier gap in non-x86 sweeps**: Phase 3 (SinkArgClassifier + SanitizerDetector) runs only on x86-64 in fortinet_sweep.py. ARM32, ARM64, PPC sweeps get taint analysis but no sink argument classification.

6. **corpus_miner.py flywheel gap**: `FindingCorpusMiner` reads re/*_re.py via AST. It does not call FindingRegistry. These are parallel stores — corpus_miner mines human-written RE modules; FindingRegistry stores sweep-registered findings with embeddings. No bridge between them exists in the sweeps layer.

7. **win16_mz_dos_sweep.py uniqueness**: The only sweep with no sentence-transformers dependency and no ablation.analyzers imports. Standalone. No FindingRegistry integration. Findings cannot feed back into the registry flywheel.
