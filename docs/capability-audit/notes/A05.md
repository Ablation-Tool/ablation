# Unit A05: Taint Trackers — MIPS / PPC / RISC-V / ARC

Covers 12 files in `ablation/analyzers/`. Two distinct tracker families:
- **Binary-path** trackers: operate on raw ELF bytes, use `Dict[str, bool]` register taint
- **Labeled** trackers: operate on structured `Insn` streams, use `Taint(labels, bound)` model

---

## MIPS32TaintTracker

- **file**: `ablation/analyzers/taint_tracker_mips.py:1-569`
- **category**: Taint Analysis / MIPS
- **entry_point**: `MIPS32TaintTracker.from_path(path, endian='little')` — NO `from_context()` method
- **what_it_does**: Source-to-sink interprocedural static taint analysis for MIPS32 O32 ELF binaries. Seeds taint from network input sources (recv/read/fgets etc.), propagates through register ALU ops and loads, detects when attacker-controlled data reaches command execution or memory copy sinks.
- **inputs**: ELF binary path (MIPS32 big- or little-endian); ELF parsed via pyelftools for PLT/func_starts; Capstone for decode
- **outputs**: `List[TaintFinding]` — each with `func_va`, `sink_va`, `sink_name`, `tainted_args`, `source_name`; `report()` → plain text
- **scope**: MIPS32 O32 ABI; big-endian (routers, Cisco) and little-endian; RouterOS, Broadcom set-top, enterprise appliances
- **sources**: `recv`, `recvfrom`, `recvmsg`, `read`, `fread`, `fgets`, `gets`, `getline`, `scanf`, `fscanf`, `sscanf` + `@plt` variants; seeds `$v0`
- **sinks**: `system`, `execve`, `execl`, `execvp`, `execlp`, `popen`, `strcpy`, `strncpy`, `strcat`, `strncat`, `sprintf`, `snprintf`, `fprintf`, `printf`, `memcpy`, `memmove`, `memset`, `bcopy`, `write`, `send`, `sendto`
- **abi_details**: O32 — `$a0-$a3` (4 arg regs), `$v0/$v1` return, `$t0-$t9` caller-saved, `$s0-$s7` callee-saved. Branch delay slot: next instruction after branch/jump executes before branch takes effect; tracker consumes delay slot (`i += 1`) before processing branch. Prologue fallback: `addiu $sp, $sp, -N` (opcode 0x09, rs=29, rt=29, imm<0).
- **status**: implemented
- **has_from_context**: **NO** — only `from_path()`. This is a notable gap: per CLAUDE.md, `from_path()` on stripped binaries returns ~22 func_starts. Use BinaryContext and inject func_starts via constructor `ctx` parameter... but MIPS32TaintTracker has no ctx parameter. **Gap: must use prologue scan fallback on stripped binaries.**
- **evidence**: `tests/test_taint_mips.py`, `tests/test_sink_arg_classifier_mips.py`
- **doc**: `docs/reference-modules/` — no dedicated MIPS32 taint tracker reference doc found in A05 assignment (no `mips32-taint-tracker.md` in reference-modules/). Known-anomalies: `docs/reference-anomalies/mips32-taint-tracker.md` (5 anomalies: KA-001 stack taint, KA-002 delay slot edge case, KA-003 indirect JALR not followed, KA-004 endian default little/wrong for BE, KA-005 no loop fixpoint)
- **limitations**: No stack taint tracking (false negatives for buffer-pass flows). No loop fixpoint. Default endian is little-endian (must pass `endian='big'` for enterprise targets). No `from_context()`. MAX_FUNC_BYTES = 32768.
- **dependencies**: `capstone` (required), `pyelftools` (PLT/symbols), optionally `lief`

## MIPS64TaintTracker

- **file**: `ablation/analyzers/taint_tracker_mips64.py:1-752`
- **category**: Taint Analysis / MIPS64
- **entry_point**: `MIPS64TaintTracker.from_path(path, endian='big')` AND `MIPS64TaintTracker.from_context(ctx, endian='big')` — has both
- **what_it_does**: Source-to-sink interprocedural taint for MIPS64 N64 ABI ELF binaries. Extends MIPS32 coverage to 64-bit DADD/DADDU/DADDIU/DSUB/shifts. Supports custom sinks. XOR rd, rd, rd correctly clears taint. MFHI/MFLO conservatively clears taint (unknown HI/LO result).
- **inputs**: ELF path or BinaryContext; LIEF preferred, pyelftools fallback; Capstone for decode
- **outputs**: `List[TaintFinding64]` — `func_va`, `sink_va`, `sink_name`, `tainted_args`, `source_name`; `report()` → str
- **scope**: MIPS64 N64 ABI; big-endian (Cisco IOS/IOS-XE, OCTEON SoCs) and little-endian (RouterOS 64)
- **sources**: `recv`, `recvfrom`, `recvmsg`, `read`, `pread`, `fread`, `fgets`, `gets`, `getenv` + `@plt` variants
- **sinks**: Default + custom via `custom_sinks` dict parameter
- **abi_details**: N64 ABI — `$a0-$a3` ($4-$7) PLUS Capstone `$t0-$t3` ($8-$11) = 8 total arg registers. `$t4-$t7` ($12-$15) are callee-saved (different from O32 where t4-t7 are caller-saved). `$v0/$v1` return. No branch delay slots (tracker still calls `_exec_non_branch()` for 64-bit ops).
- **status**: implemented
- **has_from_context**: **YES** — `from_context(ctx, endian='big')`
- **evidence**: `tests/test_taint_mips.py` (shared file)
- **doc**: `docs/reference-anomalies/mips64-taint-tracker.md` (5 anomalies: KA-001 N64 t-reg aliasing, KA-002 stack taint, KA-003 indirect JALR, KA-004 endian default big/wrong for LE, KA-005 no loop fixpoint). No reference-modules doc in A05 assignment.
- **limitations**: N64 only (no O32 MIPS64 support). No stack taint. No loop fixpoint. Default endian big-endian. MAX_FUNC_BYTES = 0x8000.
- **dependencies**: `capstone`, `lief` (preferred), `pyelftools` (fallback)

## TaintTracker (MIPS32/64 Labeled)

- **file**: `ablation/analyzers/taint_tracker_mips_labeled.py:1-916`
- **category**: Taint Analysis / MIPS (Labeled)
- **entry_point**: `TaintTracker(mode=Mode.MIPS32, abi=None, policy=None)` constructor; no `from_path()` or `from_context()`. Input via `run(insns)`, `step(insn)`. Consumes `Insn` stream from `insn_mips.from_listing`, `from_objdump`, `from_capstone`.
- **what_it_does**: Forward labeled-taint tracker for MIPS32 (O32) and MIPS64 (N64) instruction streams. Uses `Taint(labels: FrozenSet[str], bound: Optional[int])` model with CFG-compatible `TaintState` (copy/join/same_as). Tracks bounds on attacker-controlled values (e.g., after `andi` instruction). Supports both mode variants via `Mode.MIPS32` / `Mode.MIPS64`.
- **inputs**: `Iterable[Insn]` from `insn_mips` module; mode set at construction
- **outputs**: `List[Finding]` — `address`, `kind` (tainted-load-address, tainted-store-address, tainted-return-address, tainted-indirect-jump, tainted-indirect-call, tainted-overwrite-of-saved-ra, tainted-syscall-number, tainted-syscall-arg, bounded-*), `detail`, `labels`
- **scope**: MIPS32 O32 and MIPS64 N64. Both endiannesses. Branch delay slots handled: branch-likely slots joined path-insensitively. MIPS64 narrowing: 32-bit-result ops sign-extend from bit 31; bound only survives if below 2^31.
- **abi_details**: `taint_register(reg, label)`, `taint_memory(base, offset, label, length)`, `taint_pointee(base, offset, label, length)` public API for seeding. Full `Policy` dataclass controls reporting (taint_through_pointer, calls_propagate_to_return, report_tainted_branch, bounded_index_is_safe, etc.). TaintState has lattice join with widen option.
- **status**: implemented
- **has_from_context**: No (listing-based, not ELF-direct)
- **evidence**: `tests/test_taint_mips.py`
- **doc**: Referenced in `docs/reference-modules/named-taint-sources-and-bounds.md` (assigned to A04 not A05). No dedicated reference doc. Reference anomalies: none dedicated — shared via MIPS32 anomaly doc.
- **limitations**: No `from_path()`/`from_context()` — requires structured Insn stream. For ELF files use taint_tracker_mips.py instead.
- **dependencies**: `ablation.analyzers.insn_mips`, `ablation.analyzers.isa_mips`

## NanoMIPSTaintTracker

- **file**: `ablation/analyzers/taint_tracker_nanomips.py:1-679`
- **category**: Taint Analysis / nanoMIPS
- **entry_point**: `NanoMIPSTaintTracker.from_path(path, endian='little')` — NO `from_context()`
- **what_it_does**: Source-to-sink taint analysis for nanoMIPS (variable-width 16/32/48-bit instruction) ELF binaries. Dual execution path: full register-level decode via Capstone 6.x with nanoMIPS support, or conservative frame-walk fallback via `NanoMIPSDecoder` on Capstone 5.x. On fallback, marks all `$a0-$a3` tainted after any source call (no false negatives, possible false positives). Implements BALC target decoding for both P32 and P16 forms.
- **inputs**: ELF path; pyelftools for PLT/symbols; Capstone 6.x (optional) for full decode; `NanoMIPSDecoder` for fallback
- **outputs**: `List[NanoMIPSTaintFinding]` or `List[NanoMIPSInterproceduralPath]`; `report()` → str noting full/conservative mode
- **scope**: O32-compatible ABI (same register names as MIPS32). Ingenic JZ4780/X1000/X2000, MediaTek Helio embedded, MIPS32r6 microcontrollers. No branch delay slots.
- **sources**: `recv`, `recvfrom`, `recvmsg`, `read`, `fgets`, `gets`, `fread`, `getline`, `scanf`, `fscanf`, `sscanf` + `@plt` variants
- **sinks**: `system`, `execve`, `execl`, `execvp`, `execlp`, `popen`, `strcpy`, `strncpy`, `strcat`, `strncat`, `sprintf`, `snprintf`, `fprintf`, `memcpy`, `memmove`, `bcopy`, `write`, `send`, `sendto`
- **abi_details**: O32 register layout. No delay slots. Call: BALC (P32: bits[31:26]=0x2a, 26-bit signed offset; P16: bits[15:10]=0b110010, 10-bit offset), JALRC. Return: JRC $ra. PLT stubs: 12 bytes each.
- **status**: implemented
- **has_from_context**: **NO** — only `from_path()`
- **evidence**: None found in tests/
- **doc**: `docs/reference-modules/nanomips.md` — matches code well. Documents BALC decode, conservative fallback, has_full_decode flag, P48 gap. `docs/reference-anomalies/nanomips-taint-tracker.md` (4 anomalies: KA-001 conservative fallback FPs, KA-002 P48 not modelled, KA-003 indirect JALRC not followed, KA-004 no loop fixpoint)
- **limitations**: No stack taint. No loop fixpoint. P48 instructions (LI48, ADDIU48) not taint-tracked. Capstone 5.x fallback over-approximates (false positives). MAX_FUNC_BYTES = 32768. No `from_context()`.
- **dependencies**: `nanomips_decoder.NanoMIPSDecoder`, `nanomips_decoder.NanoMIPSDisasm`, `pyelftools`, optionally Capstone 6.x

## PPC32TaintTracker

- **file**: `ablation/analyzers/taint_tracker_ppc32.py:1-1069`
- **category**: Taint Analysis / PPC32
- **entry_point**: `PPC32TaintTracker.from_path(path, endian='big', **kwargs)` AND `PPC32TaintTracker.from_context(ctx, endian='big', **kwargs)` — has both
- **what_it_does**: Source-to-sink interprocedural taint for PPC32 System V / EABI ELF binaries. GOT2 PIC resolver for Huawei bootloaders (vendor reloc type 0x40000054 causes LIEF to discard all PLT entries; falls back to raw dynsym loading). Per-function r30 value computed by scanning PIC prologue (`bcl/mflr r30/addis/addi` pattern). Handles both standard SYSV PLT and GOT2 PIC indirect calls (`lwz rX, N(r30)` + `mtctr rX` + `bctrl`). Custom sinks via `custom_sinks` parameter. Includes CLI entry point.
- **inputs**: ELF path or BinaryContext; LIEF + pyelftools for ELF parsing; Capstone for decode
- **outputs**: `List[TaintFindingPPC32]` — `binary`, `func_va`, `func_name`, `sink_va`, `sink_name`, `tainted_args` (arg index list), `source_name`; `report()` → str
- **scope**: PPC32 big-endian (Cisco 7200/3700 IOS, MikroTik RB600, VxWorks, Huawei S6720) and little-endian (POWER LE Linux). System V / EABI.
- **sources**: `recv`, `recvfrom`, `recvmsg`, `read`, `pread`, `fread`, `fgets`, `gets`, `getenv` + `@plt` variants. Buffer argument register varies by source: `recv`/`read` → r4 (buffer); `fgets`/`gets`/`fread` → r3.
- **sinks**: `system`, `execv`, `execvp`, `execve`, `execl`, `execle`, `execlp`, `popen`, `strcpy`, `strcpy_s`, `strcat`, `strcat_s`, `sprintf`, `sprintf_s`, `snprintf`, `snprintf_s`, `memcpy`, `memcpy_s`, `memmove`, `malloc`, `calloc`, `realloc` + custom sinks
- **abi_details**: System V: `r3-r10` (8 arg regs), `r3` return, `r0/r3-r12` caller-saved, `r13-r31` callee-saved. No delay slots. GOT2 PIC: r30 = per-function GOT2 anchor. `_func_r30` dict maps func_va → r30 value. Indirect call via CTR: `lwz rX, N(r30)` → `mtctr rX` → `[crclr]` → `bctrl`.
- **status**: implemented
- **has_from_context**: **YES** — `from_context(ctx, endian='big')`
- **evidence**: `tests/test_sink_arg_classifier_ppc32.py` (classifier tests, not direct tracker tests)
- **doc**: `docs/reference-modules/ppc32-taint-tracker.md` — matches code well. **DOC-CODE MISMATCH**: Reference doc says "tracker taints r3 from the return value, not the buffer contents" and "A finding requires the byte count to reach a sink register." Code actually taints the BUFFER argument register (r4 for recv/read, r3 for fgets). The byte count (r3) is also tainted for some cases but the primary taint seed is the buffer register. This is a misleading doc that could cause false negative assumptions.
- **doc also**: `docs/reference-anomalies/ppc32-taint-tracker.md` (5 anomalies: KA-001 stack taint, KA-002 GOT2 internal function pointers, KA-003 LIEF Huawei guard may fire on SYSV PIC, KA-004 endian default, KA-005 no loop fixpoint)
- **limitations**: No stack taint. No loop fixpoint. GOT2 internal callee resolution gaps. MAX_FUNC_BYTES = 0x8000. LIEF Huawei fallback guard (`if not self._plt`) can theoretically fire on unusual SYSV PIC binaries.
- **dependencies**: `capstone` (required), `lief` (preferred), `pyelftools` (fallback)

## PPC64TaintTracker

- **file**: `ablation/analyzers/taint_tracker_ppc64.py:1-713`
- **category**: Taint Analysis / PPC64
- **entry_point**: `PPC64TaintTracker.from_path(path, endian='big', **kwargs)` AND `PPC64TaintTracker.from_context(ctx, endian='big', **kwargs)` — has both
- **what_it_does**: Source-to-sink interprocedural taint for PPC64 ELFv1/ELFv2 binaries. Extends PPC32 to 64-bit (LD/STD, MULLD, DIVD, 64-bit shifts/rotates, RLDIC*, EXTSW). Supports both big-endian (IBM AIX, old Linux PPC64, FortiOS 6.x) and little-endian (OpenPOWER ELFv2). Custom sinks via `custom_sinks`. Includes CLI entry point. Simpler than PPC32: no GOT2 resolver (uses LIEF/pyelftools PLT directly).
- **inputs**: ELF path or BinaryContext; LIEF + pyelftools; Capstone
- **outputs**: `List[TaintFindingPPC64]` — same structure as PPC32
- **scope**: PPC64 ELFv2 (OpenPOWER Linux) and ELFv1 (AIX, old Linux PPC64). IBM POWER, Juniper MX/PTX with POWER processors, FortiOS 6.x hardware.
- **sources**: Same set as PPC32 (recv, recvfrom, recvmsg, read, pread, fread, fgets, gets, getenv + @plt)
- **sinks**: Smaller default set than PPC32 (no strcpy_s/sprintf_s variants); custom_sinks parameter
- **abi_details**: Same as PPC32: `r3-r10` args, `r3` return, no delay slots. ELFv1: function descriptors in .opd (requires Ppc64ElfV1Resolver before running for stripped ELFv1). Prologue scan: `stdu r1, -N(r1)` (opcode=62, XO=1, rs=1, ra=1, negative 14-bit ds).
- **status**: implemented
- **has_from_context**: **YES** — `from_context(ctx, endian='big')`
- **evidence**: `tests/test_ppc64_be_call_scanner.py` (related but not direct taint tracker test), `tests/test_sink_arg_classifier_ppc64.py`, `tests/test_sink_arg_classifier_ppc64_elfv2_callee.py`
- **doc**: `docs/reference-modules/ppc64-taint-analysis.md`. **DOC-CODE MISMATCH (HIGH — MISLEADS AGENT)**: Reference doc states "provides the same labeled-taint model as TaintTrackerARM64 but for PPC64 BE." This is **FALSE**. PPC64TaintTracker uses `Dict[str, bool]` boolean taint, NOT labeled taint (no `Taint(labels, bound)` model). The labeled PPC tracker is in `taint_tracker_ppc_labeled.py` (class `TaintTracker`). An LLM agent reading this doc would incorrectly assume label propagation, label-based reporting, or bound tracking exists in PPC64TaintTracker.
- **doc also**: `docs/reference-anomalies/ppc64-taint-tracker.md` (5 anomalies: KA-001 ELFv1 stripped binaries, KA-002 TOC pointer not emulated, KA-003 stack taint, KA-004 endian default, KA-005 no loop fixpoint)
- **limitations**: No stack taint. No loop fixpoint. ELFv1 stripped binaries require Ppc64ElfV1Resolver preprocessing. TOC-slot internal function pointers not resolved. MAX_FUNC_BYTES = 0x8000.
- **dependencies**: `capstone` (required), `lief` (preferred), `pyelftools` (fallback)

## TaintTracker (PPC32/64 Labeled)

- **file**: `ablation/analyzers/taint_tracker_ppc_labeled.py:1-~800+`
- **category**: Taint Analysis / PPC (Labeled)
- **entry_point**: `TaintTracker(mode=Mode.PPC64, abi=None, policy=None, little=False)` constructor; consumes `Insn` stream from `insn_ppc` module
- **what_it_does**: Forward labeled-taint tracker for PPC32 and PPC64 instruction streams. Uses `Taint(labels, bound)` model with CFG-compatible `TaintState`. Handles full PPC instruction set: LMW/STMW multi-register loads/stores, ISEL, CR logic/move, SPR moves, FP loads/stores/moves, EXTSW/EXTS*, ROTLW/ROTLD bit rotations with INSERT. Separate modes for PPC32 (32-bit ptr) and PPC64 (64-bit ptr). `_zext32` method handles 32-bit zero-extend in PPC64 mode.
- **inputs**: `Iterable[Insn]` from `insn_ppc`; mode set at construction (Mode.PPC32 or Mode.PPC64)
- **outputs**: `List[Finding]` with typed kinds (same taxonomy as MIPS labeled tracker)
- **scope**: PPC32 and PPC64. Both endiannesses (via `little=False` parameter). No branch delay slots. Link register `lr` is the RA register (not `$ra`). CR register tracking.
- **abi_details**: `taint_register(reg, label)`, `taint_memory(base, offset, label, length)`, `taint_pointee(base, offset, label, length)` public API. Family-based register normalization via `isa_ppc.family()` and `canon_reg()`. The `ra_regs` set tracks registers holding saved LR values.
- **status**: implemented
- **has_from_context**: No (listing-based)
- **evidence**: `tests/test_taint_ppc.py`
- **doc**: No dedicated reference doc found. Not listed in A05 reference doc assignments (assignments focus on binary-path PPC trackers). This is an undocumented module in the reference docs system.
- **limitations**: No `from_path()`/`from_context()`. Requires structured Insn stream.
- **dependencies**: `ablation.analyzers.insn_ppc`, `ablation.analyzers.isa_ppc`

## ARCTaintTracker

- **file**: `ablation/analyzers/taint_tracker_arc.py:1-548`
- **category**: Taint Analysis / ARC
- **entry_point**: `ARCTaintTracker.from_path(path, endian='little', **kwargs)` AND `ARCTaintTracker.from_context(ctx, endian='little', **kwargs)` — has both
- **what_it_does**: Source-to-sink interprocedural taint for ARC EM/HS (ARCv2, 32-bit) ELF binaries. Uses `ARCDecoder` (pure-Python) for instruction decode since Capstone 5.x has no CS_ARCH_ARC support. Handles ARC-specific code-density compact instructions (push_s, pop_s, enter, leave). Tracks BLINK register as return address. No delay slots in standard ARC (optional .d suffix not modelled).
- **inputs**: ELF path or BinaryContext; LIEF/pyelftools for PLT/symbols; `ARCDecoder` from `arc_decoder.py`
- **outputs**: `List[TaintFindingARC]`; `report()` → str
- **scope**: ARC 700 and ARC HS (EM, HS3x/4x/5x). ARC Linux ABI: r0-r7 args (8 regs), r0 return, r0-r12 caller-saved, r13-r25 callee-saved, r28=SP, r31=BLINK. Synopsys DesignWare IoT SoCs, smart TV SoCs, automotive, Seagate/WD storage controllers.
- **sources**: `recv`, `recvfrom`, `recvmsg`, `read`, `pread`, `fread`, `fgets`, `gets`, `getenv` + `@plt` variants
- **sinks**: `system`, `execv`, `execvp`, `execve`, `popen`, `strcpy`, `strcat`, `sprintf`, `snprintf`, `memcpy`, `memmove`, `malloc`, `calloc`, `realloc` + custom sinks
- **abi_details**: r0-r7 (8 arg regs), r0 return, r31=BLINK (link register / RA). Call: `bl <target>`, `jl [reg]`. Return: `j_s [blink]` or `j [blink]`. Compact 16-bit instructions via `arc_decoder`.
- **status**: implemented (partial — depends on ARCDecoder coverage; full Capstone decode not available in CS5)
- **has_from_context**: **YES** — `from_context(ctx, endian='little')`
- **evidence**: `tests/test_taint_arc.py`
- **doc**: `docs/reference-anomalies/arc-taint-tracker.md` (4 anomalies: KA-001 partial ARCDecoder coverage, KA-002 16-bit compact limited, KA-003 indirect JL not followed, KA-004 no loop fixpoint). No reference-modules doc in A05 assignment.
- **limitations**: ARCDecoder is pure-Python, not Capstone; coverage of DSP/EM extensions and vendor custom opcodes incomplete. 16-bit compact decode is best-effort. No stack taint. No loop fixpoint. MAX_FUNC_BYTES = 0x8000.
- **dependencies**: `arc_decoder.ARCDecoder`, `lief` + `pyelftools`

## Doc-Code Mismatches

### HIGH — Likely to Mislead LLM Analyst

1. **`docs/reference-modules/ppc64-taint-analysis.md`** — Claims "provides the same labeled-taint model as TaintTrackerARM64 but for PPC64 BE." **FALSE.** `PPC64TaintTracker` uses `Dict[str, bool]` boolean taint, not `Taint(labels, bound)`. An agent using this doc would incorrectly expect label names, bound tracking, or labeled finding output from PPC64TaintTracker. The labeled PPC tracker is in `taint_tracker_ppc_labeled.py` (class `TaintTracker`).

2. **`docs/reference-modules/ppc32-taint-tracker.md`** — States "The tracker taints r3 from the return value, not the buffer contents. A finding requires the byte count to reach a sink register." **PARTIALLY FALSE.** Code at line 858-860: `buf_reg = _BUFFER_ARG_REG.get(target_name, 'r4'); tainted[buf_reg] = True`. The tracker seeds the BUFFER argument register (r4 for recv/read/pread/recvfrom, r3 for fgets/gets/fread/getenv), not only r3. This doc could lead an agent to incorrectly conclude no finding is possible for the common case where recv fills a buffer and sprintf uses it.

### MEDIUM — Potentially Misleading

3. **`taint_tracker_ppc_labeled.py`** has no reference doc at all. It is the "correct" labeled taint tracker for PPC analysis, but the PPC64 reference doc points to the wrong (boolean) tracker as if it were labeled. Agents looking for PPC labeled taint analysis will be sent to the boolean tracker.

4. **Reference docs for ppc32-func-discovery.md, ppc32-got2-resolver.md, ppc32-heap-slot-overflow.md, ppc32-ppc476-dedicated-lifting.md, sac-ppc32-be.md, verified-ppc32-import-callers.md** are assigned to unit A05 but describe OTHER modules (PPC32GOT2Resolver, ppc32_plt_tracer, ppc476_lifter, SinkArgClassifier PPC32, etc.) that are not in the A05 file set. These docs are correctly assigned in docs/INDEX.md but the work unit assignment is somewhat misleading.

### LOW — Minor Gaps

5. No reference-modules doc exists for MIPS32TaintTracker, RISCV32TaintTracker, RISCV64TaintTracker, ARCTaintTracker, or TaintEngine (RISC-V labeled). Their only documentation is in `reference-anomalies/` which covers failure modes but not usage patterns.

6. `nanomips.md` reference doc references `tracker._plt_map` (as `_plt_map`) but the code uses `self._plt` (as `_plt`). The dict is named `_plt` in the code (line 451: `self._plt: Dict[int, str] = {}`). Low impact as this is an internal attribute name, not a public API.
