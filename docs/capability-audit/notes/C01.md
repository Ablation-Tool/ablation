## Capability: BinaryParser — universal magic-byte format dispatch

- **file:** ablation/core/binary_parser.py
- **status:** IMPLEMENTED (with known limitations)
- **entry point:** `BinaryParser(filepath)` → `.detect_format()` → `.parse()` → dict; `.report()` → str
- **what it does:** Reads the first 512 bytes of a file, identifies ELF/PE/Mach-O from magic bytes, then calls `_parse_elf()`, `_parse_pe()`, or `_parse_macho()` to extract basic metadata (entry point, section count, arch). Returns a dict or formatted string.
- **deps:** pure Python (struct)
- **formats:** ELF32, ELF64, PE32, PE32+ (MZ magic), Mach-O 32/64
- **known gaps:**
  - Section name resolution is broken: uses raw name_offset integer, not the string table.
  - Endian bug in ELF32 big-endian: `shentsize` parsed with hardcoded `'<H'` (little-endian) regardless of `EI_DATA`.
  - No XCOFF, COFF M88K, APK, or BFF dispatch — those are handled by dedicated parsers directly.
- **ref docs:** none matching in reference-modules/

## Capability: ELFParser — comprehensive pure-Python ELF32/64 parser

- **file:** ablation/core/elf_parser.py (1367 lines)
- **status:** IMPLEMENTED
- **entry point:** `parse_elf(path)` → `ELFParser`; `ELFParser(path)` → `.parse()` → self
- **what it does:**
  - Parses ELF32/64 headers: e_ident, e_type, e_machine, entry point.
  - Program headers: PT_LOAD, PT_DYNAMIC, PT_INTERP, PT_GNU_STACK, PT_GNU_RELRO.
  - Section headers: .text, .data, .bss, .got.plt, .dynsym, .symtab, .dynamic, .rela.plt, .rel.plt.
  - Dynamic section: DT_NEEDED (shared libs), DT_RPATH/DT_RUNPATH, DT_PLTGOT, DT_BIND_NOW.
  - Symbol tables: dynsym + symtab (imports and exports).
  - `detect_security()`: PIE (ET_DYN), NX stack (PT_GNU_STACK without PF_X), RELRO (partial/full), stack canary (__stack_chk_fail), fortify (_chk functions), stripped (.symtab absent).
  - `got_plt_analysis()`: section addresses, imported/exported functions, GOT writability, hooking surface.
  - `scan_infection_indicators()`: relative RPATH, suspicious DT_NEEDED, multiple DT_INIT, EP outside .text, high text entropy (>7.0), absent section header table.
  - `get_plt_got_table()`: parses .rela.plt/.rel.plt, resolves symbol names, detects GOT overwrites. LoongArch64 uses plt_idx=2 (2-slot PLT header).
  - `_vaddr_to_file_offset()`: VA→file offset via PT_LOAD segments; skips the ELF-header pseudo-segment (p_vaddr==0, p_offset==0).
- **deps:** pure Python (struct)
- **arches:** i386, MIPS, PPC, PPC64, ARM, x86-64, AArch64, LoongArch64 (EM=258)
- **known gaps:** Does not parse DWARF debug info (.debug_info, .eh_frame). No DWARF unwinding.
- **ref docs:** none matching (aix-xcoff32-64-analysis.md covers XCOFF, not ELF)

## Capability: TLSAnalyzer — live TLS network probe and cipher analysis

- **file:** ablation/core/tls_analyzer.py (2771 lines — largest core file)
- **status:** IMPLEMENTED
- **entry point:** `TLSAnalyzer` class → `.analyze(host, port=443, timeout=8)` → dict; `.analyze_hosts(targets)` → list; `.report(results)` → str

- **what it does:** 20 analysis steps per host:

  2. Deprecated version detection (SSLv2/3, TLS 1.0/1.1 per RFC 8996).
  3. Broken cipher suites: RC4/3DES/NULL/EXPORT/ANON cipher acceptance.

  5. CT poison detection (pre-cert OID 1.3.6.1.4.1.11129.2.4.3 in live cert).
  6. HSTS/HPKP headers via HTTP GET.
  7. Quantum vulnerability inventory: RSA/ECDSA/DH/DSA = Shor-vulnerable; ML-KEM/ML-DSA/SLH-DSA/Falcon = safe (NIST FIPS 203/204/205).
  8. GCM nonce reuse risk via session resumption probe.
  9. Anon cipher acceptance.
  10. EXPORT cipher acceptance.
  11. Session ticket lifetime check (>86400s = HIGH).
  12. HSTS socket-level probe.
  13. HTTP→HTTPS redirect check.
  14. DNS zone transfer (AXFR) via raw wire-format query to port 53.
  15. OCSP stapling check (TLS_EXT_STATUS_REQUEST echo in ServerHello).
  16. Protocol downgrade probes: SSLv3 (POODLE, CVE-2014-3566), TLS 1.0 (BEAST, CVE-2011-3389), TLS 1.1.
  17. Forward secrecy: ECDHE/DHE vs RSA key exchange acceptance.
  18. CT SCT presence (X.509 extension OID 1.3.6.1.4.1.11129.2.4.2 or DER byte scan).
  19. RC4/NULL/EXPORT cipher probes.
  20. TLS compression (CRIME, CVE-2012-4929): DEFLATE in ServerHello.
  - Also: client auth bypass probe, session resumption abuse (forged session ID), BEAST CBC check, DH parameter extraction (Logjam prime fingerprint matching against RFC 2409/3526 MODP groups).

## Capability: AixInstallpDecompressor — IBM AIX installp BFF compression (steps 1–4)

- **file:** ablation/core/aix_installp_decompressor.py (653 lines)
- **status:** IMPLEMENTED (step 4 single-level verified; multi-level hypothesis unconfirmed)
- **entry point:** `AixInstallpDecompressor(raw: bytes)` → `.decompress()` → bytes; `.bwt_buffer()` → bytes; `.round_trip_verify(xcoff_bytes)` → dict
- **what it does:**
  - Full 4-step IBM installp decompression pipeline for BFF entries with type bytes 0x0c/0x0e/0x0f/0x10/0x11:
    - Step 1: Unary MSB-first Huffman decode (N consecutive 1-bits + 0-bit encodes MTF index N).
    - Step 2: Inverse MTF transform (initial list = frequency-sorted 256-byte sym_table).
    - Step 3: Inverse BWT via LF-mapping (numpy). Handles multi-cycle BWT (K<256) — reconstructs only the main cycle; T[0..n-cycle_len-1] is unrecoverable (IBM proprietary cycle ordering in liblpp.a).
    - Step 4: Single-level escape-byte decode. Rare bytes encoded as [escape_byte, term] pairs.
  - Header parsing: type 0x0c = AIX 4.3.3 BE variant; 0x0e = standard (field_A=uncomp_size, field_C_LE=bwt_index); 0x0f = inverted (field_A=bwt_index, field_C_LE=uncomp_size); 0x10/0x11 = empirical RE (layout uncertain).
  - Decoder verified correct via synthetic round-trip: XCOFF32 magic 0x01df produced from automountd PPC32 code.
  - Multi-cycle BWT root cause documented: IBM's reduced-alphabet (K=56) compression causes 19 disjoint LF-map cycles for automountd; IBM decoder's cycle concatenation order is not derivable from the BWT data alone.
- **deps:** numpy (for inverse BWT), struct (stdlib)
- **formats:** AIX BFF installp compressed entries (types 0x0c, 0x0e, 0x0f, 0x10, 0x11)
- **ref docs:** aix-installp-decompressor.md

## Capability: BwtEulerianReconstructor — IBM multi-cycle BWT circuit reconstructor

- **file:** ablation/core/bwt_eulerian_reconstructor.py (302 lines)
- **status:** IMPLEMENTED (circuit construction works; IBM's specific ordering not recoverable)
- **entry point:** `BwtEulerianReconstructor(bwt_last)` → `.reconstruct(policy, start_node, main_cycle_rows)` → bytes; `.cycle_structure()` → dict; `.verify_against_known_segment(circuit, known_segment, offset)` → dict
- **what it does:**
  - Attempts to recover T_step4[0..87815] (the portion of IBM automountd's step4-encoded text unrecoverable by standard LF-map traversal) via Eulerian circuit on the K-node directed multigraph of the BWT matrix.
  - Hierholzer's algorithm with three edge-selection policies: GREEDY, NON_MAIN_FIRST, BWT_INDEX_FIRST.

## Capability: GuardianPAKExtractor — Tandem NSK Guardian PAK archive extractor

- **file:** ablation/core/guardian_pak_extractor.py (255 lines)
- **status:** IMPLEMENTED
- **entry point:** `iter_files(data: bytes)` → Iterator[GuardianFile]; `iter_chunks(data)` → Iterator[bytes]; `extract_to(data, dest)` → List[GuardianFile]
- **what it does:**
  - Parses Tandem Guardian PAK (NonStop Kernel corrective service PTF) archive format (magic b'PAK ').
  - Format: 8-byte header + 2-byte subtype; then zlib-compressed chunks (2-byte BE size, 0xFFFF=group separator); EOF signaled by two consecutive 0xFFFF sentinels.
  - Inside decompressed chunks: Guardian BACKUP tape records. **Type codes are NOT stable** across archives (confirmed: same record class has different codes in different PTF archives). All detection is content-based:
    - Tape label: 200-byte record containing b'Tandem Archive Tape'.
    - File catalog: 222-byte record containing b'File Backup'.
    - File header: 358-byte record with b'$' at offset 0x2E (Guardian 3-component path).
    - Data blocks: any other record following a file header.
  - `_parse_guardian_path()`: extracts (volume, subvolume, filename) from the 24-byte space-padded field at offset 0x2E in file headers (e.g. "$DEV2.ZMQP00.1EALTMQF").
  - `GuardianFile`: path, volume, subvolume, filename, data, arch="mips32be" (Himalaya K-series hardware).
  - Existence reason: `UNPAK` requires a live Tandem NSK system; `unzip`/`file`/`binwalk` all reject PAK files.
- **deps:** zlib, struct (stdlib)
- **formats:** Guardian PAK (NSK corrective service PTF archives)
- **ref docs:** none matching (no guardian/nsk reference doc found)

## Capability: ShellcodeUtils — shellcode generation, ROP analysis, exploit helpers

- **file:** ablation/core/shellcode_utils.py (1647 lines)
- **status:** IMPLEMENTED
- **entry point:** Multiple functions (no class wrapper); `shellcode_reverse_tcp_linux_x86_64(lhost, lport)`, `shellcode_reverse_tcp_linux_arm64(lhost, lport, darwin)`, `shellcode_bind_tcp_linux_x86_64(port)`, `shellcode_staged_loader(fd, map_size, platform)`, `shellcode_execve_linux_x86(path)`, `find_rop_gadgets(binary_data, base_addr)`, `compute_rop_chain_execve(gadgets, bin_sh_addr)`, `detect_bad_bytes(shellcode, bad_set)`, `encode_xor_rolling(shellcode, key)`, `encode_add(shellcode, key)`, `generate_cyclic_pattern(length)`, `find_cyclic_offset(pattern, value)`, `detect_format_string_vulnerability(binary_data)`, `detect_stack_canary(binary_data)`, `detect_nx_aslr(binary_data)`, `build_exploit_buffer(shellcode, total_size, ret_addr)`
- **what it does:**
  - **Shellcode templates (hand-assembled bytes):**
    - `shellcode_reverse_tcp_linux_x86_64`: socket/connect/dup2/execve via syscall instruction. Syscalls: socket=41, connect=42, dup2=33, execve=59.
    - `shellcode_reverse_tcp_linux_arm64`: same flow using svc #0; handles Linux dup3 (syscall 24) vs Darwin dup2 (0x200005A). Includes Darwin XNU BSD class-2 syscall numbers.
    - `shellcode_bind_tcp_linux_x86_64`: socket/bind/listen/accept/dup2/execve. Syscalls: bind=49, listen=50, accept=43.
    - `shellcode_execve_linux_x86`: JMP/CALL/POP technique with int 0x80; null-byte-free path string using placeholder 'A' overwritten at runtime.
    - `shellcode_staged_loader`: mmap(PROT_RWX) + read(fd) + jmp. x86-64 and ARM64/Darwin variants.
  - **ROP gadget scanner:** `find_rop_gadgets()` scans raw bytes for pop/ret patterns, syscall, jmp rsp. `compute_rop_chain_execve()` builds execve ROP chain (pop rax/rdi/rsi/rdx + syscall).
  - **Bad byte detection:** `detect_bad_bytes()` with predefined sets (BAD_BYTES_NULL, BAD_BYTES_HTTP, BAD_BYTES_SQL, BAD_BYTES_COMMON).
  - **Encoders with decoder stubs:** `encode_xor_rolling()` (rolling XOR, x86-64 decoder stub via CALL/POP + loop); `encode_add()` (ADD encoder, x86-64 decoder stub).
  - **De Bruijn cyclic pattern:** `generate_cyclic_pattern(length)` (62-char alphabet, n=4, up to 14.7M unique 4-byte subsequences); `find_cyclic_offset(pattern, value)` (LE + BE fallback).
  - **Format string detection:** `detect_format_string_vulnerability()` — %hhn (HIGH), %hn (HIGH), %n in format context (HIGH) or isolated (LOW), direct-parameter-access %<N>$<h*>n (HIGH).
  - **Stack canary detection:** `detect_stack_canary()` — three signals: __stack_chk_fail string, __stack_smashing_detected string, FS:[0x28]/GS:[0x14] TLS cookie read byte patterns. Confidence: HIGH (2+ signals), MEDIUM (symbol only), LOW (pattern only).
  - **NX/ASLR detection:** `detect_nx_aslr()` — reads ELF32/64 PT_GNU_STACK p_flags (PF_X bit → NX disabled) and e_type (ET_DYN=PIE, ET_EXEC=no-PIE). Both endiannesses.
- **deps:** struct, socket, platform, sys, re (all stdlib)
- **formats:** raw bytes (any); ELF for detect_nx_aslr; PE-agnostic (no PE-specific paths)
- **syscall tables:** Linux x86-64, Linux ARM64, Darwin ARM64
- **known gaps:** ARM64 shellcode encoding contains partial/incorrect instruction encoding in the connect/execve sections (hardcoded strh offsets, approximate adr displacement). Not validated against actual ARM64 execution.
- **ref docs:** none matching
